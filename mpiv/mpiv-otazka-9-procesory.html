01

Úvod do procesorů

CPU (Central Processing Unit) je „mozek" počítače. Provádí instrukce programů – načítá data, počítá, ukládá výsledky. Moderní procesory obsahují miliardy tranzistorů a běží na GHz frekvencích.

Základní komponenty CPU
  • ALU (Arithmetic Logic Unit) – provádí aritmetiku a logiku
  • Řadič (Control Unit) – dekóduje instrukce, řídí tok
  • Registry – velmi rychlá paměť uvnitř CPU
  • Cache – L1/L2/L3 rychlá vyrovnávací paměť
  • Pipeline – více instrukcí současně v různých fázích

Intel – x86-64

Intel je průkopník mikroprocesorů. Architektura x86 (1978, 8086) je nejrozšířenější pro PC a servery. CISC architektura – bohatá instrukční sada, variabilní délka instrukcí (1–15 bytů).

Architektura x86-64
  • CISC – stovky instrukcí, variabilní délka
  • 64-bit registry (RAX, RBX, RCX, RDX...)
  • Backward compatible – starý kód běží na nových CPU

Core i9-14900K

24 jader (8 P-cores + 16 E-cores), až 6.0 GHz. Hybrid architektura. Intel 7 proces (10 nm). DDR5, PCIe 5.0.

Xeon (servery)

Sapphire Rapids: až 60 jader. ECC RAM, multi-socket. Datacentra, HPC.

Klíčové technologie Intel
  • Hyper-Threading – 2 vlákna per core (SMT)
  • Turbo Boost – dynamické zvýšení frekvence
  • AVX-512 – SIMD instrukce (512-bit vektory)
  • Deep Learning Boost – AI akcelerace
03

AMD – x86-64

AMD je hlavní konkurent Intelu. Vynalezl 64-bit rozšíření x86 (AMD64). Masivní comeback s architekturou Zen.

Ryzen 9 7950X3D

16 jader / 32 vláken, až 5.7 GHz. Zen 4, TSMC 5 nm. 3D V-Cache – extra 64 MB L3 pro gaming.

EPYC Genoa (servery)

Až 96 jader / 192 vláken! Chiplet design. Dominance v serverech, HPC, cloud.

Klíčové technologie AMD
  • SMT – 2 vlákna per core (jako Intel HT)
  • Precision Boost – auto overclocking
  • Infinity Fabric – interconnect mezi chiplets
  • 3D V-Cache – vertikálně stackovaná L3 cache
  • Chiplet design – několik dies spojených (lepší výtěžnost, škálovatelnost)

04

ARM – RISC architektura

ARM (Advanced RISC Machine) je RISC architektura optimalizovaná pro energetickou efektivitu. Dominantní v mobilech, tabletech, embedded. ARM Holdings licencuje design, nevyrábí čipy.

Architektura ARM
  • RISC – jednoduchá, uniformní instrukční sada
  • Fixní délka instrukcí (32-bit nebo 16-bit Thumb)
  • Load/Store architektura – jen LD/ST přistupují k RAM
  • Velmi energeticky efektivní

ARM Cortex řady

Cortex-A (Application)

High-performance. Smartphones, tablety. A78, A710, X3 – flagship jádra. ARMv8/v9 (64-bit AArch64).

Cortex-R (Real-Time)

Deterministický, low-latency. Automotive (ADAS), storage controllers.

Cortex-M (Microcontroller)

Ultra-low power, malá plocha. M0/M3/M4/M7/M33. IoT, wearables, senzory.

ARM v desktopech a serverech

Apple Silicon (M1–M4)

Vlastní ARM design. M4: 10 jader (4P + 6E), TSMC 3 nm. Unified Memory. 20+ h baterie. Dominuje výkon/watt.

AWS Graviton 3

64 jader, Neoverse V1. 40% lepší cena/výkon než x86 v AWS cloudu.

Ampere Altra

Až 128 jader! Neoverse N1. Cloud-native servery.

VÝHODY ARM

  • Energetická efektivita
  • Škálovatelnost (MCU → servery)
  • Licenční model – každý může vyrobit

NEVÝHODY ARM

  • Méně native x86 aplikací
  • Legacy SW neběží nativně
05

RISC-V – open-source

RISC-V je OTEVŘENÁ instrukční sada (ISA). Kdokoli může navrhnout a vyrábět RISC-V procesory BEZ licenčních poplatků. Revoluční změna v CPU průmyslu!

Architektura RISC-V
  • Čistý RISC design – učí se z ARM, MIPS
  • Modulární – base ISA + optional extensions
  • RV32I / RV64I – 32/64-bit base integer
  • Extensions: M (multiply), A (atomic), F (float), D (double), C (compressed)
  • Fixní 32-bit instrukce (nebo 16-bit C extension)

RISC-V implementace

SiFive (průkopník)

U74/U84 – high-performance jádra. Freedom platformy.

ESP32-C3/C6 (Espressif)

RISC-V MCU pro IoT. WiFi/BLE integrované. Cenově dostupné.

StarFive JH7110

Quad-core 1.5 GHz. Linux support. Edge AI.

VÝHODY RISC-V

  • ZDARMA – žádné licence (vs ARM)
  • Otevřený – kdokoli může přispět
  • Modulární – přidej jen co potřebuješ
  • Čistý design bez historického baggage
  • Akademická podpora – snadné studium

NEVÝHODY RISC-V

  • Mladý ekosystém
  • Méně SW nástrojů
  • Fragmentace implementací
  • Zatím nižší výkon než top ARM/x86
Budoucnost RISC-V

RISC-V roste rychle. Predikce: dominance v embedded/IoT do 2030. Potenciál nahradit ARM v mobilech/serverech. Čína masivně investuje (nezávislost na USA tech).

Superskalární procesor

Superskalární procesor může vydat více než 1 instrukci za 1 clock cycle. Má více execution units (ALU, FPU, Load/Store) a dokáže běžet více instrukcí paralelně.

Scalar vs Superscalar

Scalar (starší): 1 instrukce per cycle → CPI = 1 (best case)

Superscalar: 4+ instrukce per cycle → IPC = 4+ (Instructions Per Cycle)

Execution Units v moderních CPU
  • Integer ALU – 4–6 units (ADD, SUB, logika)
  • FPU (Floating Point) – 2–4 units
  • Load/Store – 2–3 units (memory access)
  • Branch – 1–2 units
  • Vector (SIMD) – AVX-512, NEON units
Výkon moderních CPU (issue width)

Intel Core i9: 6-way  │  AMD Zen 4: 6-way  │  Apple M4 (P-cores): 8-way

08

Out-of-Order Execution

Moderní superskalární CPU jsou také Out-of-Order (OoO). Instrukce mohou být vykonány v JINÉM POŘADÍ než v programu, pokud to neporuší závislosti.

Příklad OoO – ušetření 98 cycles
// Program order:
1. LOAD R1, [addr]  ← pomalé, 100 cycles!
2. ADD R2, R3, R4   ← nezávislé!
3. SUB R5, R6, R7   ← nezávislé!
4. MUL R8, R1, R9   ← závisí na R1

// OoO execution:
// Cycle 1: LOAD starts (pomalé)
// Cycle 2: ADD, SUB běží (nemusí čekat!)
// Cycle 100: LOAD done
// Cycle 101: MUL běží
// → Ušetřeno ~98 cycles!
Reorder Buffer (ROB)

Fronta pro sledování instrukcí. Zajišťuje, že výsledky jsou zapsány v PŮVODNÍM POŘADÍ (pro správnost programu), i když byly vykonány mimo pořadí.

Vícejádrový procesor

~2005: Frekvence CPU dosáhly limitu (~4 GHz) kvůli power/heat. Řešení: více jader místo vyšší frekvence. „More cores, not more MHz."

Heterogenní (big.LITTLE / Hybrid)

Kombinace různých typů jader na jednom chipu.

ARM big.LITTLE

Big cores (A78) – výkonné, vysoká frekvence. LITTLE cores (A55) – efektivní, nízká spotřeba. Scheduler přepíná podle zátěže. Příklad: Snapdragon 8 Gen 3.

Intel Hybrid (P + E cores)

P-cores (Performance) – vysoký IPC. E-cores (Efficiency) – menší, úspornější. Thread Director – HW scheduler. Příklad: i9-14900K (8P + 16E = 24).

Amdahl's Law: Speedup = 1 / ((1 − P) + P/N)
P = paralelní část (0–1), N = počet jader. P=0.95, N=∞ → max speedup = 20×
Limit multi-core

Více jader pomáhá jen pokud kód je paralelní! Sériová část programu limituje celkový speedup (Amdahlův zákon).

SMT a Cache koherence

SMT (Simultaneous Multi-Threading)

Jedno fyzické jádro prezentováno jako 2 logická jádra (threads). Sdílí execution units, ale duplikované registry/state.

SMT parametry
  • Intel: Hyper-Threading
  • AMD: SMT
  • Výhoda: využití idle execution units → ~20–30% speedup
  • Příklad: 8 cores × 2 threads = 16 logical processors

Cache koherence

Problém: Core1 má X=5 v L1, Core2 změní X=10. Core1 má stará data!

MESI protokol
StavVýznam
M – ModifiedZměněno, jen v tomto cache. Musí zapsat zpět do RAM
E – ExclusiveČisté, jen v tomto cache. Shodné s RAM
S – SharedČisté, ve více caches současně
I – InvalidNeplatné – data zastaralá, musí znovu načíst

Zajišťuje konzistenci dat mezi jádry. Každý cache line má MESI stav.

11

Spekulativní provádění instrukcí

Speculative Execution: CPU začne vykonávat instrukce PŘED tím, než ví, zda jsou správné. Pokud spekulace špatná → zahození výsledků (rollback).

Proč spekulace?

Branch instrukce (if/while) způsobují zpoždění – CPU neví kam skočit dokud nespočítá podmínku. Místo čekání → hádej a běž!

Bez spekulace

1. Vyhodnoť podmínku (5 cycles). 2. ČEKEJ na výsledek. 3. Pak běž správnou větev. Pipeline BUBBLE – ztraceno 5+ cycles!

Se spekulací (správná)

1. Start podmínku. 2. SOUČASNĚ spekulativně běž větev A. 3. Podmínka TRUE → spekulace správná! Žádná bubble! Ušetřeno 5 cycles.

Spectre / Meltdown

Spekulativní execution může způsobit side-channel útoky. Spekulace čte data, která by neměla → leak přes cache timing.

Mitigace: Retpoline (SW workaround), IBRS/STIBP (HW protekce Intel), flush cache po spekulaci.

12

Predikce skoku

Branch Predictor je HW komponenta, která hádá výsledek podmíněných skoků. ~20% instrukcí jsou branches. Misprediction penalty: 10–20 cycles. Moderní CPU: 95–98% accuracy.

Statické metody

MetodaPravidloAccuracy
Always NOT TAKENVždy pokračuj sekvenčně~50%
Always TAKENVždy skoč~50%
Backward TAKEN, Forward NOT TAKENZpět = skok (loop), vpřed = ne~90% pro loops!
Proč Backward TAKEN funguje

Loop s 9 iteracemi: 9× backward branch TAKEN (správně) + 1× forward exit NOT TAKEN (správně) = 90% accuracy.

Dynamické metody

1-Bit Predictor

Pamatuje si POSLEDNÍ výsledek branche. 1 bit per branch. Problém: 2 missy per loop (začátek + konec).

2-Bit Saturating Counter

2 bity = 4 stavy. Odolnější vůči náhodným změnám. Jen 1 miss per loop!

00 Strongly NOT TAKEN
01 Weakly NOT TAKEN
10 Weakly TAKEN
11 Strongly TAKEN
Přechody 2-bit counteru

Taken → increment (max 11). Not Taken → decrement (min 00).

Loop příklad: stav = 11 (Strongly TAKEN) → 9× TAKEN → zůstává 11. Exit NOT TAKEN → 11→10. Příští loop: predikce TAKEN (10) → SPRÁVNĚ!

Pokročilé prediktory

PrediktorPrincipAccuracy
Branch History TableTabulka 2-bit counterů indexovaná PC~90%
Two-Level AdaptiveHistorie + pattern detection (T,T,N,T,T,N...)>95%
PerceptronNeuronová síť, učí se z historie97–98%

Branch Target Buffer (BTB) a RAS

BTB (Branch Target Buffer)

Cache pro TARGET adresy skoků. Nejen predikuje TAKEN/NOT TAKEN, ale i KAM skočit. Entry: [PC, Target, Prediction].

RAS (Return Address Stack)

Specializovaný stack pro CALL/RET. CALL → push, RET → pop. ~100% accuracy pro return adresy!

13

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

VÝROBCI PROCESORŮ

  • Intel – x86-64, CISC. Core i9 (24 jader, 6 GHz), Xeon servery. Hyper-Threading, Turbo Boost, AVX-512
  • AMD – x86-64, CISC. Ryzen 9 (16 jader, Zen 4), EPYC (96 jader). Chiplet design, 3D V-Cache, Infinity Fabric
  • ARM – RISC, licenční model. Cortex A/R/M. Apple M4, Graviton (64), Ampere (128). Energeticky nejefektivnější
  • RISC-V – RISC, open-source, ZDARMA. Modulární (RV32/64 + extensions). ESP32-C3, SiFive. Budoucnost embedded/IoT

SUPERSKALÁRNÍ + OoO

  • Superskalární = 4–8 instrukcí per cycle, více execution units (ALU, FPU, Load/Store)
  • Out-of-Order = instrukce v jiném pořadí, pokud neporuší závislosti → maskuje latenci
  • Reorder Buffer (ROB) = výsledky zapisovány v původním pořadí

VÍCEJÁDROVÉ

  • Multi-core = 2–128 jader, vlastní ALU/L1/L2, sdílená L3
  • Heterogenní: big.LITTLE (ARM), P+E cores (Intel). Scheduler řídí přiřazení
  • SMT / Hyper-Threading: 2 threads per core (~20–30% speedup)
  • MESI protokol: cache koherence (Modified/Exclusive/Shared/Invalid)
  • Amdahl's Law: Speedup = 1/((1−P) + P/N). Sériová část limituje!

SPEKULACE + PREDIKCE SKOKU

  • Spekulativní execution: běž instrukce PŘED zjištěním správnosti. Špatně → flush (10–20 cycles)
  • Statické: Backward TAKEN (~90% loops)
  • 1-bit: pamatuje poslední (2 missy/loop)
  • 2-bit saturating: 4 stavy (00→01→10→11), odolný (1 miss/loop)
  • Two-level / Perceptron: pattern detection, 95–98% accuracy
  • BTB: cache target adres. RAS: return stack (~100%)
  • Spectre/Meltdown: side-channel útok přes spekulaci → mitigace (Retpoline, IBRS)
Zlatá pravidla
  • x86 (Intel/AMD) dominuje PC/servery, ARM dominuje mobile/embedded, RISC-V = budoucnost open-source
  • Superskalární = více instrukcí/cycle. Multi-core = více jader paralelně
  • Spekulace + predikce (>95%) = klíč k výkonu moderních CPU
  • 2-bit counter je základ branch prediction – 4 stavy, odolný vůči výkyvům
