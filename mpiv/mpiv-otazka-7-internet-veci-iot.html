01

Co je Internet věcí

Internet of Things (IoT) je síť fyzických objektů („věcí") vybavených senzory, softwarem a konektivitou, které umožňují sběr a výměnu dat přes internet. Komunikace M2M (Machine to Machine) bez lidského zásahu.

Klíčové charakteristiky
  • Senzory – měření fyzikálních veličin
  • Konektivita – připojení k internetu/síti
  • Procesování dat – lokálně nebo v cloudu
  • Aktuátory – ovládání zařízení
  • Autonomie – funguje bez lidského zásahu

Smart Home

Termostat Nest, žárovky Philips Hue, kamery, zámky.

Wearables

Fitness trackery, smartwatches, health monitoring.

Průmysl 4.0

Prediktivní údržba, monitoring strojů, asset tracking.

Smart Cities

Parkování, doprava, osvětlení, waste management.

Statistiky
  • 2023: ~15 miliard IoT zařízení
  • 2030: predikce 30+ miliard zařízení
  • Každou sekundu připojeno ~127 nových zařízení

03

Hardware pro IoT – MCU/SoC

Požadavky na IoT MCU
  • Nízká spotřeba – bateriový provoz (roky!)
  • Wireless konektivita – WiFi/BLE/LoRa integrovaná
  • Periférie – ADC, SPI/I2C, GPIO
  • Bezpečnost – crypto akcelerátor, secure boot
  • Cena – miliony zařízení → každý cent počítá

Populární IoT MCU/SoC

ESP32 (Espressif)

Dual-core Xtensa 32-bit @ 240 MHz. WiFi + BLE 4.2. 512 KB SRAM, 4 MB Flash. Deep sleep 5 μA. Cena: $2–4.

ESP8266 (Espressif)

Single-core @ 80 MHz. WiFi only. Levnější (~$1–2). Stále velmi populární pro jednoduché projekty.

nRF52840 (Nordic)

ARM Cortex-M4 @ 64 MHz. BLE 5.0, Thread, Zigbee. Ultra-low power 4.8 μA. Crypto akcelerátor.

STM32 WL (ST Micro)

ARM Cortex-M4 + LoRa radio integrované! Sub-GHz (868/915 MHz). Ideální pro LPWAN.

Strategie úspory energie
  • Sleep majority času – wake jen pro měření a TX
  • Duty cycle – např. 1% active, 99% sleep
  • Snížit TX power – kratší dosah ale úspora
  • Batch data – shromažďuj, pošli najednou

WPAN a WLAN – BLE, Zigbee, WiFi

Bluetooth Low Energy (BLE)

BLE parametry
  • Dosah: 10–100 m
  • Data rate: 1–2 Mbps
  • Spotřeba: velmi nízká (μA v sleep)
  • Frekvence: 2.4 GHz ISM
  • Topologie: point-to-point, star, mesh (BLE Mesh)
  • Použití: wearables, beacony, proximity

Zigbee

Zigbee parametry
  • Dosah: 10–100 m
  • Data rate: 250 kbps
  • Frekvence: 2.4 GHz
  • Topologie: mesh – self-healing network
  • Až 65 000 nodes v jedné síti
  • Použití: smart home (Philips Hue, IKEA Tradfri)

WiFi (802.11)

WiFi parametry
  • Dosah: 50–100 m indoor
  • Data rate: 1–1000+ Mbps (podle standardu)
  • Spotřeba: vyšší než BLE/Zigbee
  • Frekvence: 2.4 GHz, 5 GHz
  • Výhody: vysoká rychlost, přímý internet access
  • Nevýhody: vyšší spotřeba
  • Použití: kamery, smart displaye, home automation

LPWAN – LoRa / LoRaWAN

LPWAN (Low Power Wide Area Network) – dlouhý dosah (km), velmi nízká spotřeba, nízký data rate. Ideální pro battery-powered outdoor sensors.

Co je LoRa?

LoRa je proprietární fyzická vrstva (PHY) vyvinutá Semtech. Používá Chirp Spread Spectrum (CSS) modulaci pro dlouhý dosah a odolnost vůči interferenci.

LoRa = fyzická vrstva (radio modulace). LoRaWAN = MAC protokol nad LoRa (network layer).

ParametrHodnota
Dosah (urban)2–5 km
Dosah (rural)15+ km
Dosah (line of sight)200+ km (rekord)
Data rate0.3 – 50 kbps (podle SF)
FrekvenceSub-GHz ISM (EU: 868 MHz, US: 915 MHz)
Spotřeba TX20–120 mA
Spotřeba sleep1–2 μA

Spreading Factor (SF)

SF určuje trade-off mezi rychlostí a dosahem. SF7–SF12:

SF75.5 kbpskratší
SF83.1 kbps
SF91.8 kbps
SF10980 bps
SF11440 bps
SF12250 bpsdelší dosah
Vyšší SF = pomalejší přenos, delší airtime, vyšší šance na příjem
SF7 = nejrychlejší, nejkratší dosah → SF12 = nejpomalejší, nejdelší dosah

Zabezpečení IoT – hrozby a útoky

Proč je bezpečnost kritická?
  • Miliardy zařízení připojených k internetu
  • Často slabé heslo nebo žádné
  • Firmware updates vzácné/nemožné
  • Botnet riziko – Mirai DDoS útok 2016
  • Privacy – kamery, mikrofony, senzory v domě

Network útoky

Man-in-the-Middle

Zachytávání a modifikace komunikace mezi zařízeními.

Replay Attack

Opakování zachycené legitimní zprávy pro neoprávněný přístup.

Jamming

Rušení RF signálu – znemožnění komunikace.

DDoS

Distributed Denial of Service – zahlcení serveru.

Software útoky

Malware

Trojany, ransomware infikující IoT zařízení.

Buffer Overflow

Exploit chyby ve firmwaru pro spuštění škodlivého kódu.

Default Credentials

admin/admin – nezměněná výchozí hesla.

FW Downgrade

Rollback na starší, zranitelnou verzi firmwaru.

Kryptografie pro IoT

Cíle kryptografie
  • Confidentiality – nikdo cizí nemůže číst data
  • Integrity – data nebyla změněna
  • Authentication – ověření identity odesílatele
  • Non-repudiation – nelze popřít autorství zprávy

Symetrická kryptografie

Stejný klíč pro šifrování i dešifrování.

SYMETRICKÁ

AES (Advanced Encryption Standard)

Nejpoužívanější symetrický algoritmus

Klíč: 128, 192, 256 bitů

Block cipher – bloky 128 bitů

Rychlý – HW akcelerátor v MCU

Módy: ECB, CBC, CTR, GCM

Příklad použití AES

Sensor data šifrována AES-128 před odesláním. Gateway dešifruje pomocí shared key. Rychlé a efektivní pro MCU.

Asymetrická kryptografie

Pár klíčů – public (veřejný) a private (soukromý).

ASYMETRICKÁ

RSA

Klíč: 1024–4096 bitů

POMALÝ – nevhodný pro šifrování dat

Použití: digitální podpisy, key exchange

ASYMETRICKÁ – PREFEROVÁNO PRO IoT

ECC (Elliptic Curve)

256-bit ECC ≈ 3072-bit RSA (kratší klíče!)

Rychlejší než RSA

ECDSA – digitální podpisy

ECDH – key exchange

Preferováno pro IoT (menší klíče, nižší spotřeba)

Hash funkce a HMAC

HASH

SHA-256

Jednosměrná funkce → fixed-size hash (256 bitů / 32 B)

Collision resistant

Použití: integrity check, digital signatures

MAC

HMAC

Hash + secret key

Ověřuje autenticitu i integritu zprávy

HMAC-SHA256(message, key) = hash

OTA (Over-The-Air) Update

Firmware update přes síť (WiFi/cellular). Bezpečný OTA vyžaduje:

Bezpečný OTA proces
  • Šifrovaný download – TLS
  • Digitální podpis – ověření autenticity FW
  • Rollback protection – version number check
  • Dual partition (A/B boot) – fallback pokud update failed
11

Fyzické útoky

IoT zařízení jsou často fyzicky přístupná (na sloupu, v poli, na stěně) → musí odolat fyzickým útokům.

1. Side-Channel Attacks

Analýza vedlejších projevů (side effects) během kryptografických operací.

Power Analysis

  • SPA (Simple) – měří spotřebu během crypto
  • DPA (Differential) – statistická analýza
  • Cíl: extrahovat crypto klíč!

Timing Attack

Měří čas trvání operací. Různé hodnoty → různý čas.

Obrana: constant-time algorithms

EM Analysis

Měří elektromagnetické emise z CPU/krypto chipů. Podobné power analysis.

2. Invasive Attacks

Fyzická modifikace čipu – pokročilé a drahé.

Chip Decapsulation

Chemicky odstranit plastic package, exponovat die.

Microprobing

Mikroskopická sonda pro čtení/modifikaci signálů na die.

Focused Ion Beam (FIB)

Přesně odstranit/přidat materiál na čipu. Extrémně pokročilé.

3. Semi-Invasive – Fault Injection

Vyvolat chybu v běhu programu pro bypass security.

Voltage Glitching

Krátký drop/spike napětí → přeskočí instrukci.

Clock Glitching

Manipulace clock signálu → špatné dekódování instrukce.

Laser Fault Injection

Zaměřený laser na čip → bitflip v registru/paměti.

Příklad Glitch útoku
if (password_correct) { unlock(); }
// Voltage glitch může přeskočit IF check
// → unauthorized access bez hesla!
12

Obrana proti fyzickým útokům

HSM / Secure Element

Dedikovaný crypto chip (TPM). Klíče nikdy neopustí čip. Tamper-resistant packaging.

Secure Enclave

Izolovaná část CPU pro security operace. ARM TrustZone, Apple Secure Enclave.

Tamper Detection

Sensory detekující opening case, voltage glitch. Reakce: smazat klíče, lock device.

Code Obfuscation

Ztížit reverse engineering. Dummy operace maskují spotřebu.

Flash Encryption

FW šifrován ve Flash, dešifrován on-the-fly. Čtení extractorem → nečitelné.

JTAG/Debug Protection

Disable JTAG v produkci. Nebo lock s heslem. Znemožní debugging.

13

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

CO JE IoT + ČTYŘI PILÍŘE

  • IoT = síť fyzických objektů se senzory a konektivitou. M2M komunikace, 15+ miliard zařízení
  • 4 pilíře: Sensing (senzory) → Computing (Edge/Cloud) → Connectivity (BLE/WiFi/LoRa) → Analytics (ML, dashboardy)
  • MCU: ESP32 (WiFi/BLE), nRF52 (BLE), STM32WL (LoRa)

NAPÁJENÍ

  • Power modes: Active (mA) → Light Sleep (800 μA) → Deep Sleep (5 μA) → Hibernation (1 μA)
  • Strategie: duty cycle (99% sleep), batch data, snížit TX power
  • Energy harvesting: solar, piezo, RF, termo

KOMUNIKACE

  • WPAN: BLE (10–100 m, μA), Zigbee (mesh, 250 kbps, 65k nodes)
  • WLAN: WiFi (50–100 m, Mbps, vyšší spotřeba)
  • LPWAN: LoRa/LoRaWAN (2–15 km, 0.3–50 kbps, CSS modulace)

LoRa DETAILY

  • LoRa = PHY layer (CSS). LoRaWAN = MAC protocol
  • SF7–SF12: trade-off rychlost ↔ dosah. SF7 = 5.5 kbps/kratší, SF12 = 250 bps/delší
  • Architektura: End Device → Gateway → Network Server → App Server
  • Class A (low power) / B (scheduled) / C (continuous RX)

ZABEZPEČENÍ + KRYPTOGRAFIE

  • Hrozby: MitM, replay, jamming, DDoS, malware, default creds
  • Symetrická: AES-128/256 (rychlé, šifrování dat, HW akcelerátor)
  • Asymetrická: RSA (pomalé), ECC (preferováno pro IoT – kratší klíče)
  • Hash: SHA-256, HMAC (integrity + authentication)
  • TLS/DTLS pro zabezpečenou komunikaci. Secure Boot + OTA s podpisy

FYZICKÉ ÚTOKY + OBRANA

  • Side-channel: power analysis (SPA/DPA), timing attack, EM analysis
  • Invasive: decapsulation, microprobing, FIB
  • Fault injection: voltage/clock/laser glitching → přeskočení IF checku
  • Obrana: HSM/Secure Element, ARM TrustZone, tamper detection, Flash encryption, JTAG disable
Zlaté pravidlo

Security by Design – bezpečnost musí být od začátku! Kryptografie (AES/ECC/SHA-256) + Secure Boot + fyzická ochrana = multi-layer defense. Každá vrstva chrání tu další.
