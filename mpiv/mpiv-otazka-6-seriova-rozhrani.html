Sériová vs paralelní komunikace

Paralelní komunikace

Více vodičů (8 bitů = 8 pinů + clock + control). Rychlá – celý byte najednou. Ale: hodně pinů, EMI, skew, krátké vzdálenosti (<1 m). Dnes zastaralé (starý printer port).

Sériová komunikace

Málo vodičů – typicky 2–4 piny (TX, RX, Clock, GND). Bity jdou po sobě. Méně pinů, delší vzdálenosti, nižší EMI. Moderní trend: USB, Ethernet, PCIe – vše sériové.

Hlavní sériová rozhraní pro MCU
  • UART/USART – asynchronní, point-to-point
  • SPI – synchronní, master-slave, vysoká rychlost
  • I2C – synchronní, multi-master, adresování
  • CAN – multi-master, automotive, robustní

UART – princip a frame

UART (Universal Asynchronous Receiver/Transmitter) je nejjednodušší sériový protokol pro point-to-point komunikaci. Asynchronní = žádný clock vodič. Sender i receiver musí mít stejný baud rate.

Detailní popis frame
  • IDLE state – linka HIGH (logic 1)
  • START bit – přechod HIGH→LOW signalizuje začátek
  • DATA bits – 5–9 bitů (typicky 8), LSB first
  • PARITY bit – volitelná kontrola chyb (even/odd/none)
  • STOP bits – 1 nebo 2 bity HIGH, konec frame
03

Baud Rate a konfigurace

Baud rate = počet symbolů (bitů) za sekundu. Protože UART nemá clock, oboje strany musí používat STEJNÝ baud rate!

Baud ratePoužití
9600Klasický, spolehlivý – kompatibilita se vším
19200 / 38400 / 57600Střední rychlosti
115200Velmi běžný pro MCU – dobrý kompromis
230400 – 921600Vysoké rychlosti – kratší vzdálenosti
UBRR = (F_CPU / (16 × Baud_rate)) − 1
Příklad: 16 MHz, 9600 baud → UBRR = (16 000 000 / (16 × 9600)) − 1 = 103
Konfigurace: notace 9600 8N1

9600 baud, 8 data bitů, No parity, 1 stop bit – nejčastější nastavení.

Příklad kódu (AVR – UART 9600 8N1)
// Nastavení 9600 baud, 8N1
UBRR0 = 103; // Baud rate
UCSR0B = (1<<RXEN0) | (1<<TXEN0); // Enable RX/TX
UCSR0C = (1<<UCSZ01) | (1<<UCSZ00); // 8-bit data

void UART_Transmit(uint8_t data) {
  while (!(UCSR0A & (1<<UDRE0))); // Wait until ready
  UDR0 = data; // Send data
}
04

RS-232 – fyzický standard

RS-232 je fyzický/elektrický standard pro UART komunikaci. Definuje napěťové úrovně a konektory. UART = protokol, RS-232 = elektrická specifikace.

+3V až +15V Logic 0 (SPACE)
−3V až +3V Undefined zone
−3V až −15V Logic 1 (MARK)
Problém s MCU!

MCU UART pracuje s TTL/CMOS úrovněmi (0 V / 3.3 V nebo 0 V / 5 V). RS-232 používá ±12 V → potřeba level shifter!

MAX232 – IC pro konverzi TTL ↔ RS-232. Generuje ±10 V z +5 V pomocí charge pump. Zapojení: MCU TX → MAX232 → RS-232 TX.

ParametrHodnota
Max délka kabelu15 m (spec), prakticky až 30 m
Max baud rate20 kbps (spec), moderně až 115.2 kbps
KonektorDB-9 (9 pinů) nebo DB-25 (25 pinů)
TopologiePoint-to-point

RS-485 – diferenciální multi-point

RS-485 je diferenciální standard pro multi-point komunikaci. BUS topologie – více zařízení na jedné sběrnici. Half-duplex – jeden mluví, ostatní poslouchají.

RS-485 BUS TOPOLOGIE
[120Ω] ──── A/B bus ──── [120Ω]
         │        │        │
      Master   Slave1   Slave2
Diferenciální signál
  • 2 vodiče: A a B
  • Logic 1: A − B > +200 mV
  • Logic 0: A − B < −200 mV
  • Výhoda: rušení ovlivní oba vodiče stejně → signál se nezmění!
ParametrHodnota
Max vzdálenost1 200 metrů!
Max rychlost10 Mbps (krátké vzdálenosti)
Max zařízení32 (standardně), až 256 s repeaters
Terminace120 Ω na obou koncích sběrnice
DuplexHalf-duplex
Řízení vysílání (DE/RE)

Protože half-duplex, MCU musí ovládat kdy vysílá:

  • DE (Driver Enable) – HIGH pro TX mode
  • /RE (Receiver Enable) – LOW pro RX mode

Typicky DE a /RE spojené na jeden GPIO pin.

Použití RS-485

Průmysl

PLC, senzory, Modbus RTU protokol. Odolné, dlouhé vzdálenosti.

DMX512

Stage lighting – ovládání divadelních a koncertních světel.

RS-422 – diferenciální full-duplex

RS-422 je diferenciální standard podobný RS-485, ale full-duplex. Má samostatné páry pro TX a RX.

VlastnostRS-422RS-485
DuplexFull-duplex (4 vodiče: TX+/TX−, RX+/RX−)Half-duplex (2 vodiče: A, B)
TopologiePoint-to-point nebo 1 driver + 10 receiversMulti-point (32 zařízení)
Max vzdálenost1 200 m1 200 m
Max rychlost10 Mbps10 Mbps
Kdy RS-422 vs RS-485?

RS-422 – high-speed point-to-point linky kde potřebuješ full-duplex. RS-485 – když potřebuješ více zařízení na jedné sběrnici.

08

SPI – clock režimy a komunikace

SPI má 4 režimy definované kombinací CPOL (Clock Polarity) a CPHA (Clock Phase). Master a Slave MUSÍ používat stejný mode!

CPOL a CPHA
  • CPOL=0: Clock idle LOW, active HIGH
  • CPOL=1: Clock idle HIGH, active LOW
  • CPHA=0: Data sampled na první edge, changed na druhé
  • CPHA=1: Data changed na první edge, sampled na druhé
ModeCPOLCPHAPoznámka
Mode 000Nejběžnější
Mode 101
Mode 210
Mode 311Druhý nejčastější
SPI Clock = CPU_clock / prescaler
Prescaler: 2, 4, 8, 16, 32, 64, 128 → Typicky 1–20 MHz, teoreticky až 100+ MHz

VÝHODY SPI

  • Vysoká rychlost (MHz)
  • Full-duplex
  • Jednoduchý protokol
  • Žádná adresace – jen SS

NEVÝHODY SPI

  • Mnoho pinů (4+ pro každý slave)
  • Krátké vzdálenosti (<1 m)
  • Žádná error detection
  • Jen master-slave (ne multi-master)
Příklad kódu (AVR – SPI Master)
// Master init
SPCR = (1<<SPE) | (1<<MSTR) | (1<<SPR0); // Enable, Master, clk/16

uint8_t SPI_Transfer(uint8_t data) {
  SPDR = data; // Start transmission
  while (!(SPSR & (1<<SPIF))); // Wait
  return SPDR; // Return received byte
}

Typické SPI periférie

Převodníky

Wireless

nRF24L01, LoRa moduly

09

I2C – princip a adresování

I2C (Inter-Integrated Circuit, „I-squared-C") je synchronní, multi-master sběrnicový protokol vyvinutý Philipsem. Pouze 2 vodiče pro adresovatelnou komunikaci s mnoha zařízeními.

2 signálové vodiče (+ GND)
  • SDA (Serial Data) – obousměrná data linka
  • SCL (Serial Clock) – clock generovaný masterem
I2C – OPEN-DRAIN S PULL-UP REZISTORY
Vcc ─[4.7 kΩ]─┬─ SDA      Vcc ─[4.7 kΩ]─┬─ SCL
              ├─ Master                  ├─ Master
              ├─ Slave1                  ├─ Slave1
              └─ Slave2                  └─ Slave2
Open-drain princip
  • Zařízení může jen pull LOW (připojit k GND)
  • Pull-up rezistor táhne linku HIGH
  • Umožňuje wired-AND logiku – základ arbitrace!

7-bit adresování

Každé I2C zařízení má unikátní 7-bit adresu (0x00–0x7F, celkem 128 adres). Některé rezervované → dostupných ~112 adres.

AdresaZařízení

0x68RTC DS1307, Gyroskop MPU6050
0x3C / 0x3DOLED displej SSD1306
0x76 / 0x77Senzor BMP280

I2C – komunikace a arbitrace

START a STOP podmínky

Signály na sběrnici
  • START (S): SDA falls HIGH→LOW zatímco SCL HIGH
  • STOP (P): SDA rises LOW→HIGH zatímco SCL HIGH
  • Data platná když SCL HIGH, data se mění když SCL LOW
  • ACK: receiver pulls SDA LOW (potvrzení přijetí)
  • NACK: SDA zůstane HIGH (konec nebo chyba)

Multi-master a arbitrace sběrnice

I2C podporuje více masterů na jedné sběrnici. Co když 2 mastery začnou vysílat současně? I2C má elegantní řešení: wired-AND arbitrace.

Princip arbitrace
1

2
Každý master monitoruje SDA během vysílání
3
Master vysílá 1 ale vidí 0 → někdo jiný táhne LOW
4
Ten master OKAMŽITĚ přestane a čeká
5

Výsledek: BEZ KOLIZE! Jeden dokončí, druhý zkusí znovu.
Clock stretching

Slave může držet SCL LOW pokud potřebuje více času na zpracování. Master musí čekat. Užitečné pro pomalé slave devices.

CAN – Controller Area Network

CAN je robustní multi-master sběrnicový protokol vyvinutý Boschem pro automotive. Extrémně odolný vůči chybám a rušení. Používá se v autech, průmyslu, robotice.

Diferenciální sběrnice
  • CAN_H (CAN High) a CAN_L (CAN Low)
  • Dominant bit (0): CAN_H = 3.5 V, CAN_L = 1.5 V (diff = 2 V)
  • Recessive bit (1): CAN_H = CAN_L = 2.5 V (diff = 0 V)
Dominant (0) CAN_H 3.5V, CAN_L 1.5V
Recessive (1) CAN_H = CAN_L = 2.5V

CAN Arbitrace (Non-Destructive)

CAN NEpoužívá adresy! Každá zpráva má Message ID. Všichni přijímají všechny zprávy, filtrují podle ID.

Wired-AND arbitrace
  • Dominant (0) přebíjí Recessive (1)
  • Node s nižším ID (více 0) vždy vyhraje
  • Prohrávající node okamžitě přestane vysílat
  • NON-DESTRUCTIVE – vítězná zpráva není poškozena!
PŘÍKLAD CAN ARBITRACE
Node A vysílá ID 0b00101 (priorita 5)
Node B vysílá ID 0b00011 (priorita 3)

Bit 0: A=0, B=0 → oboje OK
Bit 1: A=0, B=0 → oboje OK
Bit 2: A=1, B=0 → B vítězí! A přestane.
→ Node B dokončí zprávu bez kolize.

Na zkoušku si zapamatuj

UART / RS-232

  • UART – asynchronní, point-to-point, 2 vodiče, START-DATA-STOP frame
  • RS-232 – ±12 V úrovně, MAX232 level shifter, DB-9 konektor
  • Baud rate – obě strany MUSÍ mít stejný! UBRR = (F_CPU / (16 × Baud)) − 1

RS-485 / RS-422

  • RS-485 – diferenciální, half-duplex, multi-point, 1200 m, 32 zařízení, terminace 120 Ω
  • RS-422 – full-duplex, 4 vodiče, point-to-point nebo 1:10

SPI

  • Synchronní, full-duplex, master-slave, 4+ pinů (SCLK/MOSI/MISO/SS)
  • 4 modes (CPOL/CPHA) – Mode 0 nejběžnější. MHz rychlosti, žádná error detection
  • Periférie: SD karty, Flash, TFT displaye, ADC/DAC, wireless moduly

I2C

  • 2 vodiče (SDA/SCL), open-drain + pull-up 4.7 kΩ, 7-bit adresy
  • Multi-master s wired-AND arbitrací. ACK/NACK mechanismus
  • 100–400 kbps typicky. Periférie: senzory, RTC, EEPROM, OLED

CAN

  • Diferenciální, multi-master, message-based (11/29-bit ID, ne adresy!)
  • Non-destructive arbitrace – nižší ID vyhraje, dominant přebíjí recessive
  • 5× error detection (CRC, frame, ACK, bit monitoring, bit stuffing)
  • Automotive, průmysl, terminace 120 Ω na obou koncích
Kdy co použít?
  • UART – jednoduché point-to-point (debug, GPS, Bluetooth modul)
  • RS-485 – průmysl, multi-point, dlouhé vzdálenosti
  • SPI – rychlé lokální periférie (displeje, Flash, SD karty)
  • I2C – mnoho senzorů na 2 vodičích (adresování)
  • CAN – kritické automotive/průmyslové aplikace
