01

Co je mikrokontrolér

Mikrokontrolér (MCU) = kompletní počítačový systém na jednom čipu. Obsahuje CPU, paměť (RAM, Flash) a periférie (GPIO, timery, ADC, komunikace) – vše integrováno.

Mikroprocesor (μP)

Pouze CPU na čipu. Externí RAM, ROM, periférie nutné. Vyšší výkon, vyšší spotřeba. Příklady: Intel x86, ARM Cortex-A. Použití: PC, servery, smartphony.

Mikrokontrolér (MCU)

CPU + paměť + periférie na jednom čipu (SoC). Kompaktní, nízká cena, nízká spotřeba. Příklady: ATmega328, STM32, ESP32. Použití: embedded, IoT, automotive.

Klíčové vlastnosti MCU
  • Integrace – vše na jednom čipu
  • Real-time – deterministické chování
  • Low power – μA až mA (bateriové napájení)
  • Dedicated purpose – jedna specifická úloha
  • Affordable – cena od pár korun

03

Von Neumann architektura VON NEUMANN

Jediná sběrnice a jediný paměťový prostor pro program i data. Instrukce a data sdílejí stejnou cestu k CPU.

CPU
ALU + Control
←→
Jediná sběrnice
Jednotná paměť
Program + Data (sdílené)

Výhody

Jednoduchost, levnější HW. Flexibilní poměr program/data. Self-modifying code možný.

Nevýhody

Von Neumann bottleneck – nelze fetch instrukce a data současně! Nižší výkon při intenzivním data access.

Příklady: Intel x86/x64, ARM Cortex-A, ARM Cortex-M0 (pro jednoduchost).

04

Harvard architektura HARVARD

Oddělené sběrnice a oddělené paměťové prostory pro program a data. Paralelní přístup!

Program Memory
Flash (instrukce)
←→
Program Bus
CPU
←→
Data Bus
Data Memory
RAM (data)

Výhody

Vyšší propustnost – paralelní fetch instrukce + data access. Deterministický timing. Ideální pro real-time. Lepší pipelining.

Nevýhody

Složitější HW (dvě sběrnice, více pinů). Dražší. Fixní poměr program/data paměti. Self-modifying code obtížný.

Příklady: AVR (ATmega – Arduino), PIC, ARM Cortex-M (STM32, nRF52) – většina moderních MCU.

05

Modified Harvard

Hybridní přístup – best of both worlds

Oddělené I-Bus a D-Bus pro CPU, ale možnost přístupu k program memory jako k datům (čtení konstant z Flash → šetří RAM). Instrukční cache oddělená od data cache.

Používá: ARM Cortex-M, moderní x86 (interně). Nejpoužívanější v moderních systémech.

06

Instrukční sada (ISA)

ISA (Instruction Set Architecture) = abstraktní rozhraní mezi HW a SW. Definuje jaké instrukce procesor rozumí, jak jsou kódované, jaké registry existují, jak se adresuje paměť.

ISA určuje
  • Instrukční set – dostupné operace (ADD, SUB, LOAD, STORE, BRANCH…)
  • Datové typy – 8/16/32/64 bit integer, float
  • Registry – počet, velikost, special-purpose
  • Addressing modes – jak se specifikují operandy
  • Memory architecture – Von Neumann vs Harvard

Dvě hlavní filosofie: CISC a RISC

07

CISC Complex Instruction Set Computer

Filosofie: „Čím více instrukcí, tím lépe"

Komplexní instrukce, které dělají HODNĚ práce. Variabilní délka (1–15+ B). Instrukce mohou přímo přistupovat k paměti. Microkód překládá na μops.

Výhody

Kompaktní kód – méně instrukcí = menší program. Menší „semantic gap". Backward compatibility (x86 od 1978!).

Nevýhody

Složitý HW (dekódování variabilních instrukcí). Pomalejší clock. Obtížné pipelining. Vyšší spotřeba. Mnoho instrukcí se málo používá.

Příklady: Intel x86/x64 (PC, servery), Motorola 68000, VAX.

08

RISC Reduced Instruction Set Computer

Filosofie: „Keep it simple"

Malý set jednoduchých, rychlých instrukcí. Komplexní operace se skládají z více jednoduchých. Fixní délka (32 bit). Load/Store architektura.

7 RISC principů
1
Malý instrukční set (~100 instrukcí)
2
Fixní délka instrukcí (32 bit)
Zjednodušuje dekódování a pipelining
3
Load/Store architektura
POUZE Load/Store přistupují k paměti. Aritmetika = register-to-register
4
Jednoduché addressing modes (2–5)
5
Velký register file (16–32 GP registrů)
6
Hardwired control (žádný microkód)
7
Pipelined execution → CPI ≈ 1

Příklad: Load/Store vs CISC přímý přístup

RISC (ARM)
LDR R0, [R1] ; Load z paměti
ADD R0, R0, R2 ; R0 = R0 + R2
STR R0, [R1] ; Store zpět
CISC (x86)
ADD [EBX], ECX ; 1 instrukce!
; Load + Add + Store
; vše v jednom

Příklady RISC: ARM (Cortex-M/A), RISC-V (open-source), MIPS, AVR (Arduino).

Moderní realita

Hranice mezi RISC a CISC se stírá. Moderní x86 interně překládá CISC instrukce na RISC-like μops. ARM přidává komplexnější instrukce (NEON, SVE). Hybridní přístupy jsou norma.

10

Mikroarchitektura

ISA vs Mikroarchitektura

ISA = „CO" procesor dělá – abstraktní interface, programátorský model.

Mikroarchitektura = „JAK" procesor implementuje ISA – fyzický hardware (datapath, pipeline, cache, branch prediction).

Příklad: ARM Cortex-M0, M3, M4 všechny implementují ARM ISA, ale mají různé mikroarchitektury (různý pipeline, execution units).

Co mikroarchitektura zahrnuje
  • Datapath – jak data proudí čipem
  • Pipeline organization – kolik stages, funkce v každém
  • Cache hierarchy – L1/L2 velikost, associativity
  • Branch prediction – jak predikovat skoky
  • Execution units – ALU, FPU, SIMD
Příklad: ARM Cortex-M0
  • 32-bit RISC jádro, Von Neumann (pro jednoduchost)
  • 3-stage pipeline (Fetch, Decode, Execute)
  • 16 general-purpose registrů (R0–R15)
  • Thumb instruction set (16-bit instrukce → lepší code density)
  • Velmi nízká spotřeba – ideální pro IoT

Instrukční cyklus

Základní cyklus vykonání jedné instrukce má 5 fází:

F
FETCH – Načtení instrukce
PC obsahuje adresu → CPU načte instrukci z program memory. Instruction = Memory[PC]
D
DECODE – Dekódování
Zjistí se operace, registry, operandy. Control unit generuje řídící signály.
E
EXECUTE – Vykonání
ALU provede operaci. Pro LOAD/STORE: ALU počítá adresu. Pro BRANCH: vyhodnocení podmínky.
M
MEMORY ACCESS – Přístup k paměti
Pouze LOAD/STORE: čtení/zápis dat. Ostatní: NOP.
W
WRITE BACK – Zápis výsledku
Výsledek zapsán do cílového registru.

Bez pipeline: Všech 5 stages sekvenčně pro každou instrukci → CPI = 5. Pomalé!

Pipeline Hazards (překážky)

Data Hazard (RAW)

Instrukce potřebuje výsledek předchozí, která ještě není hotová. ADD R1,R2,R3 → SUB R4,R1,R5 (R1 ještě neexistuje!). Řešení: Forwarding/Bypass nebo pipeline stall (bubble).

Control Hazard (Branch)

BRANCH instrukce – nevíme kam skočit, pipeline neví co fetchovat. Řešení: Branch prediction, delay slot, pipeline flush.

Structural Hazard

Dvě instrukce potřebují stejný HW resource současně (např. fetch + load na Von Neumann). Řešení: Harvard arch (oddělené sběrnice), resource duplication.

13

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

MIKROKONTROLÉR

  • MCU = CPU + paměť + periférie na jednom čipu. Low-power, dedicated, real-time
  • Mikroprocesor = pouze CPU, externí RAM/ROM/periférie (PC, servery)

PAMĚŤOVÉ ARCHITEKTURY

  • VON NEUMANN Jediná sběrnice, jednoduché, flexibilní. Bottleneck! (x86, Cortex-A)
  • HARVARD Oddělené sběrnice, paralelní přístup, deterministické. Složitější HW. (AVR, PIC, Cortex-M)
  • Modified Harvard = hybridní, best of both. Nejpoužívanější dnes

ISA: RISC vs CISC

  • RISC ~100 instrukcí, fixní délka (32 b), Load/Store only, 16–32 registrů, CPI≈1, low power. ARM, RISC-V, AVR
  • CISC 100–1000+ instrukcí, variabilní délka, přímý memory access, microkód, kompaktní kód. x86
  • Moderní realita: hranice se stírá (x86 interně RISC-like μops, ARM přidává složitější instrukce)

MIKROARCHITEKTURA A PIPELINE

  • ISA = CO procesor dělá. Mikroarchitektura = JAK to implementuje (pipeline, cache, branch prediction)
  • Instrukční cyklus: Fetch → Decode → Execute → Memory → Write Back
  • Pipeline: překrývání instrukcí → CPI ≈ 1 (5× throughput vs sekvenční)
  • Hazards: Data (RAW → forwarding), Control (Branch → prediction), Structural (→ Harvard arch)
