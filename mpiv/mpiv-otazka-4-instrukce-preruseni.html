01

5 fází instrukčního cyklu

Klasický RISC procesor vykonává instrukci v 5 fázích:

F
FETCH – Načtení instrukce
PC → adresa na memory bus → instrukce do IR. IR ← Memory[PC]; PC ← PC + 4
D
DECODE – Dekódování
Extrahuj opcode, registry, immediate. Generuj control signals. Čti hodnoty registrů.
E
EXECUTE – Vykonání
ALU provede operaci. Status flags: Z (zero), N (negative), C (carry), V (overflow), H (half carry).
M
MEMORY ACCESS – Přístup k paměti
Pouze LOAD/STORE. L1 cache: 1–2 cy, L2: 5–10 cy, RAM (miss): 50–200 cy!
W
WRITE BACK – Zápis výsledku
Výsledek → cílový registr. STORE: žádný WB (data už v memory).
Non-pipelined (sekvenční)

Všech 5 fází sekvenčně pro každou instrukci → CPI = 5. Během Execute je Fetch unit idle → plýtvání HW!

Řešení Data Hazards

A) Forwarding (Bypass)

Nejlepší! Výsledek z Execute/Memory I1 přímo forward do Execute I2. Bez čekání na WB. Žádný stall! Složitější HW (bypass mux).

B) Pipeline Stall (Bubble)

Zastavit I2 dokud I1 nedokončí WB. Vložit NOP do pipeline. Ztráta 2–3 cycles! Jednoduchý HW.

C) Compiler Scheduling

Kompilátor přeuspořádá instrukce – vloží nezávislou instrukci mezi I1 a I2. Žádný stall, jednoduchý HW. Ne vždy možné.

04

Control Hazards (Branch)

Branch instrukce – nevíme kam skočit dokud se nevyhodnotí podmínka (Execute stage). Pipeline už fetchovala následující instrukce!

Problém

Pipeline fetchuje I3, I4 sekvenčně… ale pokud branch taken → I3, I4 jsou ŠPATNÉ instrukce! 20–30 % instrukcí jsou branches → velký impact!

Řešení

A) Pipeline Flush

Počkej na vyhodnocení branchu → flush špatně fetchované instrukce. 2–3 cycle penalty na každý branch.

B) Branch Prediction

Predikuj výsledek BEFORE vyhodnocení. Správná → žádný stall! Špatná → flush (2–3 cy). Moderní CPU: >95 % accuracy!

C) Branch Delay Slot

Instrukce za branchem se VŽDY vykoná (MIPS, SPARC). Kompilátor naplní užitečnou instrukcí nebo NOP.

Branch Prediction – Static vs Dynamic

Static: Predict NOT TAKEN (sekvenčně), nebo Backward TAKEN / Forward NOT TAKEN (loops).

Dynamic (2-bit saturating counter):

00Strongly NOT
01Weakly NOT
10Weakly TAKEN
11Strongly TAKEN

Predikce se změní až po 2 špatných výsledcích → stabilnější. Branch History Table (BHT) ukládá historii.

05

Structural Hazards

Dvě instrukce potřebují stejný HW resource současně. Příklad (Von Neumann): I1 Memory stage (LOAD data) + I4 Fetch stage (LOAD instruction) – obě potřebují memory bus!

Řešení
  • Harvard architektura – oddělené instruction a data bus → eliminuje
  • Separate I/D cache (Modified Harvard)
  • Multi-ported memory / register file
  • Pipeline stall – jeden počká (špatný výkon)
06

Přerušení vs Výjimky

INTERRUPT (Přerušení)

Asynchronní – nezávislé na aktuální instrukci. Externí zdroj – HW periférie. Lze maskovat. Příklady: Timer overflow, UART RX, GPIO pin change, ADC complete.

EXCEPTION (Výjimka)

Synchronní – způsobená aktuální instrukcí. Interní – chyba v CPU/programu. Většinou nelze maskovat. Příklady: Divide by zero, invalid instruction, stack overflow.

Typy přerušení
  • Hardware Interrupts – externí pin (INT0, INT1), periférie (timer, ADC, UART)
  • Software Interrupts – vyvolané instrukcí (SWI), syscalls v OS
  • NMI (Non-Maskable) – nejvyšší priorita, nelze zamaskovat! Power failure, watchdog, HW error

08

Interrupt Vector Table

Vector = adresa handleru (ISR) pro konkrétní přerušení. Vector table = tabulka adres na začátku Flash paměti (0x0000).

Příklad Vector Table (ATmega328)
0x0000RESETPower-on / reset (nejvyšší priorita)
0x0002INT0External Interrupt Request 0
0x0004INT1External Interrupt Request 1
0x0006PCINT0Pin Change Interrupt 0
……
0x0020TIMER0_OVFTimer/Counter0 Overflow
0x0022TIMER0_COMPATimer0 Compare Match A
…celkem 26 vektorů

Nižší adresa = vyšší priorita (AVR fixed priority).

09

Obsluha přerušení (ISR) – 8 kroků

1Detekce – HW detekuje IRQ, interrupt flag nastaven
2Finish instruction – CPU dokončí aktuální instrukci (atomic)
3Save context – HW uloží PC + SREG na stack. SW může push další registry
4Clear I flag – I=0 automaticky → zabrání nested interrupts (default)
5Vector fetch – PC načte adresu z vector table → skok na ISR
6Execute ISR – zpracování události, update dat, nastavení flags
7Clear IRQ flag – HW automaticky nebo manuálně (jinak infinite loop!)
8RETI – obnoví PC+SREG ze stacku, I=1, pokračuje odkud přerušen
ISR Best Practices
  • Krátké! Minimalizuj čas v ISR → maximize responsiveness
  • volatile proměnné pro sdílená data mezi ISR a main()
  • Žádný blocking – delay(), printf(), busy-wait loops
  • Flag pattern – set flag v ISR, process v main loop
  • CLI/SEI kolem multi-byte read/write
  • Žádná floating-point math (pomalá, velký context save)
Příklad ISR kódu (AVR)
volatile uint16_t milliseconds = 0;

ISR(TIMER0_OVF_vect) {
  milliseconds++; // Inkrementuj čítač
  // IRQ flag cleared automaticky HW
  // RETI automaticky na konci
}
10

Priorita a Nested Interrupts

AVR – Fixed Priority

Priorita daná pozicí ve vector table. Nižší adresa = vyšší priorita. RESET (0x0000) > INT0 (0x0002) > … > USART_RX. Nested: NE (default, I=0 v ISR).

ARM Cortex-M – NVIC

Nested Vectored Interrupt Controller. Programmable priority 0–255 (0 = nejvyšší). Preemption – vyšší priorita přeruší nižší ISR. Nested: ANO (HW podpora).

Interrupt Latency

Čas od IRQ assertion do první instrukce ISR. Kritické pro real-time!

Komponenty latency
FázeCycles
Instruction completion1–N
Context save (push PC, SREG)2–5
Vector fetch2–3
Jump to ISR1–2
Celkem typicky6–15+ cycles
Faktory zvyšující latency
  • Kritické sekce (CLI) – interrupt čeká až SEI
  • Vyšší prioritní ISR už běží
  • Cache miss – fetch ISR kódu z RAM
  • Dlouhá instrukce (division 10+ cy)

AVR @ 16 MHz: best 5 cy = 0.3 μs, typical 10 cy = 0.6 μs, worst (CLI) 1000+ cy = 62+ μs.

12

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

INSTRUKČNÍ CYKLUS & PIPELINE

  • 5 fází: Fetch → Decode → Execute → Memory → Write Back. Non-pipelined CPI = 5
  • Pipeline: překrývání → CPI ≈ 1, throughput 5×. Latency stejná!

HAZARDY

  • Data (RAW): instrukce potřebuje výsledek předchozí → Forwarding (best), Stall, Scheduling
  • Control (Branch): nevíme kam skočit → Branch Prediction (>95%), Flush, Delay Slot
  • Structural: stejný HW resource → Harvard arch, separate cache

PŘERUŠENÍ

  • Interrupt = asynchronní, externí HW, lze maskovat. Exception = synchronní, interní chyba, většinou ne
  • Podmínky: I flag = 1 AND individual enable = 1 AND IRQ flag = 1
  • Maskování: SEI enable, CLI disable. Kritické sekce pro atomic operace

ISR & VEKTORY

  • Vector table: na začátku Flash (0x0000+). Nižší adresa = vyšší priorita (AVR fixed)
  • ISR 8 kroků: Detekce → Finish inst → Save context → I=0 → Vector fetch → Execute → Clear flag → RETI
  • ISR pravidla: krátké, volatile, žádný blocking, flag pattern
  • ARM NVIC: programmable priority (0–255), nested interrupts HW podpora
  • Latency: 6–15 cycles typicky. Kritické pro real-time
