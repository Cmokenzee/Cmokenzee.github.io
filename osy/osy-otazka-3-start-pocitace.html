01

Start PC – dvě fáze

Start počítače se dá rozdělit na dvě snadno rozlišitelné části. Pro různé typy počítačů je postup specifický.

Inicializace hardware

Řeší firmware – software od výrobce na základní desce. V IBM PC to byl BIOS, nově UEFI.

Zavedení operačního systému

První krok provede firmware, další postup je čistě v režii použitého software.

Filozofie u PC: „zresetuj to a ono to (nejspíš) bude fungovat." U pracovních stanic a serverů to někdy nestačí.

02

Zapnutí PC – reset, CPU, BIOS

FÁZE 1
Reset
Po zapnutí PC nebo stisku tlačítka „reset". Reset je el. signál propojující všechny obvody. Stavové obvody se uvedou do počátečního stavu – jinak by software nevěděl, jak začít s jejich ovládáním.
FÁZE 2
CPU do 16bitového režimu
Jako Intel 8086 – CPU „vidí" jen 1 MiB paměti. Interpretace kódu od adresy 0xFFFF0, kde je umístěn BIOS (zajistí výrobce základní desky).
FÁZE 3
Provádění kódu v BIOS / UEFI
Plně kontroluje první fázi startu PC.
03

BIOS a jeho rozšíření

Basic Input-Output System. Uložen v ROM (dnes Flash → lze aktualizovat), na základní desce od jejího výrobce. BIOS programuje několik firem, je modulární.

Vlastnosti BIOSu
  • Závislý na HW – přímo jej ovládá
  • Poskytuje jednoduché API – tzv. „služby BIOSu" (čti sektor z disku, vytiskni znak, pošli na port…)
  • Plně na něj spoléhal pouze DOS
  • 16bitový z původního IBM PC (1981) – 32bitová rozšíření se neujala
  • Dnes je BIOS nahrazován UEFI

Rozšíření BIOSu

  • Vlastní BIOS mají i doplňující karty (grafická, řadiče SATA/SCSI)
  • Definované rozhraní – BIOS rozšíření najde a spustí jeho inicializační kód
  • Přidám kartu, má na sobě svoji ROM s BIOSem
  • VideoBIOS – inicializace čipu grafické karty
  • Zavedení OS z jiného řadiče (SCSI, SAS, další SATA)
  • Start systému ze sítě (BootROM)
04

SETUP a CMOS

SETUP

Aplikace pro volitelná nastavení BIOSu. Dříve samostatná aplikace (problém při ztrátě diskety → přesun do BIOSu). Vyvolání při startu stiskem DEL, F2 apod. Nastavení chipsetu (frekvence, napájení), pořadí zařízení pro zavedení OS, heslo. Dříve pořadí pevně stanoveno → boot viry z disket.

CMOS

Paměť RAM s nízkou spotřebou, desítky až stovky bajtů. Nevolatilní – zálohována lithiovou baterií (spolu s RTC). Obsahuje jen hodnoty, žádný výkonný kód. V nouzi lze vymazat jumperem / vyndáním baterie → BIOS obnoví safe defaults.

Reset CMOS nemusí fungovat

U pracovních stanic a serverů může být heslo BIOSu uloženo v TPM čipu – vymazání CMOS nepomůže.

05

Činnost BIOSu při startu

1
Detekce a inicializace hardware
Uvedení HW do výchozího stavu. Lze částečně přeskočit u teplého startu.
2
ACPI tabulky
Standard (Intel, 1996) – info o konfiguraci do speciálních tabulek v paměti. Jen nové počítače (Windows 2000+). Tabulky často chybné → problém pro Linux. Tvůrce BIOSu potřebuje jen funkční start pro Windows.
3
POST testy
Power On Self Test – základní kontroly funkčnosti HW.
4
Cíl: aktivace operačního systému
Předání řízení zavaděči OS.
06

Studený × teplý start, Fast Startup

Studený start

Počítač je vypnut a zapnut. Je aktivován signál reset pro všechny obvody.

Teplý start (restart)

Tlačítko „restartovat" v nabídce systému. SW sekvence: ukončení činností → skok na startovací sekvenci v BIOSu. Lze vynechat některé kroky (reinicializaci obvodů) → rychlejší.

Fast Startup (Windows)

Hybrid boot / hybrid shutdown
  • Na počítačích podporujících hibernaci je defaultně zapnuto
  • Při zavření víka notebooku nejdříve S3 (sleep), později S4 (hibernace)
  • „Vypnutí" ve skutečnosti dělá S4 – skutečné vypnutí: SHIFT + Vypnout
  • S4 = ukončení aplikací, ale RAM s jádrem uložena na disk → soubor C:\hiberfil.sys
  • Spolupráce se stejným nastavením v BIOSu (fastboot) – přeskočí test a detekci HW
Problémy Fast Startup
  • Nefunguje vstup do BIOSu (F2, Del, Esc, F10…)
  • Možná kolize při dual boot s Linuxem → lze vypnout v nastavení Windows
  • Obsah NTFS disku není konzistentní – část změn je v RAM
07

Odkud lze OS zavést

BIOS – zdroje pro boot
  • Disketa – nejjednodušší, u ostatních slouží jako vzor (emulace)
  • Pevný disk – jako disketa, ale navíc MBR
  • CD/DVD – emulace diskety nebo přímo
  • BootROM – emulace diskety nebo přímo (PXE ze sítě)
  • USB mass storage – flash disk, externí HDD
UEFI
  • Delší dobu jej používá Apple (EFI → Intel)
  • Náhrada BIOSu, umožňuje binární „ovladače" HW
  • Problém možnosti tajit nastavování HW (kvůli DRM)
  • Zástupným důvodem odchodu od BIOSu jsou disky > 2 TiB
08

Start z diskety a boot sektor

BIOS umí disketovou mechaniku plně ovládat. FDD je ovládána na PC jednotně – potřebujeme jen načíst požadovaný sektor.

KROK 1
Inicializace FDD
Nalezení a inicializace disketové mechaniky.
KROK 2
Načtení boot sektoru
BIOS zavede do RAM první sektor diskety – prvních 512 bajtů, LBA=0 (postaru CHS = 0,0,1). Využívá své služby → HW i SW nezávislý kód.
KROK 3
Skok na boot sektor
Skočí se na začátek boot sektoru a pokračuje jeho kód.

Boot sektor

Obsahuje kód zavaděče jádra OS. Pro různé OS je boot sektor různý.

  • DOS – různé verze (MS-DOS, IBM-DOS, FreeDOS). Typický rozdíl: různě pojmenované soubory (io.sys + msdos.sys, ibmio.sys + ibmdos.sys)
  • Windows NT – u starších verzí šlo zavést systém ze čtyř disket
  • Linux – buď zavaděč (LILO, GRUB, syslinux) nebo každé jádro má vlastní boot sektor (prvních 512 bajtů binárky jádra)
  • Nenajde-li boot sektor soubory s jádrem → System files not found
09

MBR a oddíly

Z fungujícího startu z diskety vznikla myšlenka „diskety na disku" – a ještě lépe: několik disket na disku. Proto přidána další vrstva: MBR + oddíly.

Oddíly (partitions)

  • Oddíl je logické rozčlenění pevného disku (disk je velký nebo potřebujeme více FS/OS)
  • Dělení bez podpory v HW – software musí respektovat (zpětná kompatibilita)
  • Vnitřek oddílu má stejnou strukturu jako disketa
  • Popis rozdělení je uložen na začátku disku – prvních 512 bajtů (LBA=0)
  • Obsahuje zavaděč a tabulku dělení disku na oddíly
  • DOS MBR je nezávislý na OS, jeho nástupcem je GPT

DOS MBR – struktura 512 bajtů

Zavaděč440 B
ID8 B
Tabulka oddílů64 B (4 × 16 B)
  • Zavaděč (440 B) boot sektoru – pro čtení z disku používá služby BIOSu → nezávislý na HW. Primitivní → alternativní zavaděče (GRUB, LILO)
  • Tabulka rozdělení (64 B) – limit velikosti disku/oddílu 2 TiB → řeší GPT
  • Max. 4 oddíly: primary + extended. Extended lze dál dělit na logické oddíly
  • Každý oddíl má ID – slouží k identifikaci obsahu

ID oddílů

0x05Extended
0x83Linux (ext3)
0x82Linux swap
0x07NTFS
0x04FAT16
0x0CFAT32

Windows rezervují 63 bloků (31,5 KiB) až 1 MiB mezery za MBR – místo pro pokročilé zavaděče (Grub v Linuxu).

10

Zarovnání oddílů, alternativní zavaděč

Zarovnání oddílů

Proč zarovnávat
  • Nové disky mají 4 KiB sektory
  • Souborové systémy mají také 4 KiB alokační jednotky
  • Pokud je hned za MBR (512 B) první blok, disk musí přečíst sousední bloky, aby složil 4 KiB alokační jednotku → podstatné snížení výkonu (i sekvenční zápis)
Řešení
  • Od Windows Vista zarovnání na 1 MiB – dostatečné pro jakékoliv zarovnání (stopy, cylindry, SSD, RAID stripe)
  • SSD: stránky 4–16 KiB, bloky 128–512 stránek
  • Problémy se staršími systémy a nástroji
  • Vzniká prostor pro speciální zavaděče (např. GRUB)

Alternativní zavaděč

  • Náhrada standardního MBR – umožňuje spustit různé systémy s různými volbami
  • Typicky poskytuje nabídkové menu
  • Menu umí i boot zavaděč pro Windows (je jednoduchý)

GRUB – oblíbený zavaděč pro Linux:

  • Menu, interaktivní rozhraní, změna parametrů
  • Předání parametrů jádru i startovacím skriptům
  • Umístění do MBR nebo do boot sektoru oddílu
11

Start z disku, CD, USB, PXE

Start z pevného disku

KROK 1
BIOS načte MBR
Prvních 512 bajtů z HDD. Pokud je neplatný → MBR not found.
KROK 2
Skok na MBR
Skočí se na začátek MBR (zavaděč + tabulka). Kód MBR vybere aktivní oddíl.
KROK 3
Přístup k oddílu jako k disketě
MBR zavede z aktivního oddílu boot sektor. Není-li platný → OS not found.
KROK 4
Zavedení jádra
Boot sektor zavede jádro OS (dále jako při startu z diskety).

Start z CD / DVD

Emulace diskety

Na CD/DVD je obraz diskety (soubor, max. 1,44 MB). BIOS ho zavede do paměti. Přesměrují se funkce BIOSu – čtení z diskety je ve skutečnosti z paměti.

Přímý přístup

BIOS musí rozumět formátu ISO 9660. Sektor je 2048 bajtů. Boot sektor je závislý na cílovém OS.

BootROM (PXE)

  • Rozšíření BIOSu na síťové kartě, tzv. PXE
  • Kombinace DHCP + TFTP a speciálního zavaděče
  • BootROM zjistí přes DHCP: IP, masku, bránu + navíc IP adresu TFTP serveru a název souboru zavaděče
  • BootROM stáhne zavaděč z TFTP a aktivuje ho, zavaděč zobrazí menu a dále stahuje jádro
  • Dříve NCP + IPX/SPX (Novell NetWare) – obraz diskety z NCP serveru se četl z paměti

Start z USB

  • UMS / MSC – USB mass storage, standard pro přístup k USB jako k HDD
  • Umí čtení/zápis sektoru – bez konkrétního FS
  • Bez rozšíření (NCQ) – pro výkon je lepší eSATA
  • Standardní UMS driver: Windows 2000, Linux od roku 2000
  • UMS obslouží flash disk, HDD, CD/DVD, SSD…
  • BIOS rozpozná UMS jako další běžný disk – start jako z disku (také přes MBR)
  • V BIOSu nutné zapnout USB legacy – emulace HDD nad UMS
12

UEFI a GPT

UEFI

Unified Extensible Firmware Interface (2004). Původně EFI od Intelu (1998). První ho použil Apple.

  • Ukončení závislosti na 16bitovém režimu CPU 8086
  • Podpora GPT (> 2 TiB disky), nahrazuje boot sektor
  • Binární moduly / zavaděče umístěny na zvláštním oddílu (FAT32)
  • Každý systém musí mít svůj zavaděč (Linux → Grub)
  • Podpora Secure Boot (šlo by to i do BIOSu, ale…)
  • EFI omezilo Linux – nutnost el. podpisů (Microsoft). Řeší zavaděč SHIM – je podepsaný a zavede cokoliv
  • Podpora grafického SETUPu (měl už i BIOS)

GPT – GUID Partition Table

  • 34 × 512 B = 16 KiB, nástupce MBR, součást standardu EFI
  • Odstraňuje limit 2 TiB, pracuje pouze s LBA
  • Teoreticky až 8 ZiB (8 × 10²¹ B pro blok 512 B)
  • Umožňuje více oddílů (Microsoft: 128 minus 4 rezervované)
  • Prvních 512 bajtů je falešný (ochranný) MBR
  • Záložní kopie GPT je umístěna na konci disku
  • Od roku 2013 je UEFI a GPT standardem pro PC – BIOS je už jen kvůli zpětné kompatibilitě
  • Windows 8 měly být původně jen pro UEFI

Aktivace jádra OS

1
Jádro převezme plnou kontrolu
Procesor do 32bitového režimu + privilegovaný režim.
2
Detekce a inicializace I/O zařízení
Nově pouze čtení ACPI tabulek + registrace zařízení.
3
Připojení prvního souborového systému
Root filesystem (kořenový FS) u unixových OS, disk C: u Windows (ale může být i jiné písmeno).
4
Spuštění prvního programu
Unix → /sbin/init. Windows → Windows Boot Manager.
5
Zahájení startovací sekvence
Cíl = připravený počítač (přihlašovací dialog).

Startovací sekvence OS

Byl-li obraz RAM uložen na disk (hibernace):

  • Nahrání původního jádra a jeho datových struktur
  • Nahrání paměti se spuštěnými procesy
  • Předání řízení „původnímu" jádru → aktuální procesy zaniknou
  • Rozběhnutí původních procesů

Klasická boot sequence:

  • Unixové OS: init spouští startovací skripty
  • MS Windows: Windows Boot Loader řízený záznamy v registrech
14

Secure Boot

Zavaděč (UEFI) kontroluje elektronický podpis – veřejný klíč je uložen v UEFI nebo v TPM čipu. Brání zavedení nepodepsaného systému.

Deklarovaný cíl
  • Ochrana proti útoku „Blue pill" (falešný hypervisor)
Kritika
  • Ve skutečnosti eliminace Linuxu na PC
  • Nakročení k prodejům OS jen ve variantě OEM-only (ke každému PC jeden systém, jako u mobilních zařízení)
  • U většiny PC lze v SETUPu vypnout, u firemních PC a notebooků volba někdy chybí
  • Zavaděč SHIM je podepsaný a umožňuje zavést nepodepsané jádro (jádro hlídá stav tainted)
Certifikáty Windows – červen 2026

V červnu 2026 vyprší certifikáty ve Windows. PowerShell (jako správce) musí vrátit true:

PS> [System.Text.Encoding]::ASCII.GetString((Get-SecureBootUEFI db).bytes) -match 'Windows UEFI CA 2023'

Automatické aktualizace nemusí být dostupné, pokud uživatel vypnul telemetrii nebo nemá podporovaný HW.

15

Zabezpečení startu PC

PC je modulární a implicitně moc bezpečné není.

Opatření
  • Nastavit start z disku a zaheslovat SETUP – nelze zavést alternativní systém z USB, CD, sítě
  • Zamknout skříň (Kensington Security Slot). Poškození cizí věci je trestný čin. Uzamčení v serverovně
  • Šifrování disku
  • Secure Boot, aktualizace systému, hesla, oprávnění
  • Personální opatření – pracovní předpisy, odpovědnost
BitLocker
  • Klíč XTS-AES délky 128 nebo 256 bitů
  • Nelze zpřístupnit data nebo odstranit heslo správce
  • Klíč v TPM, chráněn PIN nebo biometrikou + integrita systému
16

Mobilní zařízení, rooting, Knox

Mobily nemají obdobu pevného disku – interní flash se tváří jako část paměti. Neexistuje obdoba BIOSu, MBR, GPT nebo UEFI.

Start mobilního zařízení
  • Každý výrobce řeší start jinak
  • Obvykle se začne provádět začátek flash – zde je loader, který řídí start
  • Zavedení jádra, případně aktivace fastboot nebo recovery
  • Jádro musí znát rozdělení flash – předáno jako parametr
  • Flash rozdělena na „oddíly" s různým účelem
  • Systém je na části jen pro čtení (read-only)
  • Aplikace a uživatelská data v jiné části (read-write)
  • Uživatel normálně nemá práva správce (root)

Android

Fastboot („Odin mode")

Malý program, aktivace tlačítkem při startu. Možnost flashování přes USB kabel.

Recovery

Vymazání dat/cache, (re)flash z MicroSD. Custom recovery → flash i nepodepsaného kódu.

Motorola – fyzická ochrana

Nelze přepsat začátek flash → obtížný (nemožný) brick. Alternativní systém jako sideload (druhý OS).

Windows Phone

  • Zařízení není rootovatelné
  • Zavaděč není ochoten přijmout nepodepsaný kód – nelze (přes USB) nahrát jiný systém
  • K jádru Windows nejsou zdrojáky → těžký exploit (neznamená, že neexistuje)
  • Modifikace firmware jen přímým programováním přes služební kontakty na základní desce uvnitř zařízení (bez datasheetů)
  • Stále lze zařízení ovládnout útokem na přidružené procesory (GSM, Wi-Fi, GPS)

Rooting

  • Modifikace firmware mobilního zařízení – cílem získat práva správce (root, Administrator)
  • Využití exploitu na jádro/systém nebo přepsání systému (reflash)
  • Po rootu hrozí riziko nakažení systému
  • Akce s právy správce uživatel schvaluje (příkaz sudo)
  • Systém nabízí zjištění stavu: Nastavení → O telefonu → Stav systému (Oficiální)
  • Některé aplikace odmítnou pracovat (bankovní). Rootnutí lze maskovat

Samsung Knox

Obdoba Secure Boot na mobilu
  • Zavaděč detekuje nahrání neoficiálního firmware
  • Elektronická „pojistka" → trvalá změna v zařízení
  • Zavaděč systému si stěžuje, Odin mode píše 0x01
  • Lze obejít exploitem na jádro → proto nelze návrat ke starší verzi Androidu
  • Aplikace mohou zjistit stav systému za běhu – při porušení odmítnou pracovat (podnikové, bankovní)
17

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

DVĚ FÁZE STARTU

  • 1. Inicializace HW (firmware – BIOS/UEFI) → 2. Zavedení OS (SW)
  • Posloupnost: reset → CPU v 16bit režimu (jako 8086, adresa 0xFFFF0) → BIOS

BIOS / UEFI / CMOS

  • BIOS (1981): 16bit, ROM/Flash, služby BIOSu (API), rozšíření (VideoBIOS, SCSI, BootROM)
  • UEFI (2004, Apple první): 32/64bit, FAT32 oddíl s binárkami, Secure Boot, GPT, grafický SETUP
  • SETUP: vstup DEL/F2, pořadí bootovacích zařízení, nastavení chipsetu
  • CMOS: RAM zálohovaná baterií (jen hodnoty). Reset jumperem → safe defaults
  • Činnost: detekce HW + ACPI tabulky + POST → aktivace OS

STUDENÝ × TEPLÝ START

  • Studený: vypnutí/zapnutí, aktivován signál reset
  • Teplý: SW sekvence + skok do BIOSu, přeskočí reinicializaci
  • Fast Startup (Windows): vypnutí = S4 hibernace (hiberfil.sys), skutečné vypnutí SHIFT+Vypnout. Problémy: F2 nefunguje, kolize s dual boot, NTFS nekonzistentní

ZAVEDENÍ OS

  • Disketa: BIOS načte boot sektor (LBA=0, 512 B) → skok na něj → zavede jádro
  • HDD: BIOS načte MBR → vybere aktivní oddíl → zavede jeho boot sektor → jádro
  • CD/DVD: emulace diskety (obraz max 1,44 MB) nebo přímo (ISO 9660, sektor 2048 B)
  • USB: UMS driver, BIOS vidí jako HDD (USB legacy)
  • PXE (BootROM): DHCP → IP + TFTP server + soubor → stáhne zavaděč → jádro

MBR × GPT

  • MBR (512 B): 440 B zavaděč + 64 B tabulka (4 oddíly, z toho extended → logické). Limit 2 TiB. ID: 0x83 Linux, 0x82 swap, 0x07 NTFS, 0x0C FAT32
  • GPT (16 KiB, UEFI): až 8 ZiB, 128 oddílů, LBA-only, ochranný MBR + záložní kopie na konci disku
  • Zarovnání: Vista+ na 1 MiB (kvůli 4 KiB sektorům/alokačním jednotkám, SSD stránkám, RAID stripe)
  • Zavaděče: GRUB (Linux), Windows Boot Manager, LILO, syslinux, SHIM (podepsaný pro Secure Boot)

AKTIVACE JÁDRA + SECURE BOOT + MOBILY

  • 5 kroků: 32bit+privileg. režim → ACPI + I/O → root FS (C:) → /sbin/init / Boot Manager → start skripty
  • Secure Boot: UEFI kontroluje podpis, klíč v TPM, chrání proti Blue Pill / eliminuje Linux, lze obejít SHIM
  • BitLocker: XTS-AES 128/256, klíč v TPM + PIN/biometrika
  • Mobily: flash místo disku, Android fastboot/recovery, Knox (trvalá pojistka proti neoficiálnímu firmware), rooting = získání práv správce
