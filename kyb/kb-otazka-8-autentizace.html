01

Tři faktory autentizace

Autentizace = ověření identity. „Je to opravdu TY?" První krok v AAA (Authentication → Authorization → Accounting). 81 % data breaches = slabá/ukradená hesla.

🧠KNOW Heslo, PIN, bezpečnostní otázka. Nejběžnější ale nejslabší.
🔑HAVE Smartphone, YubiKey, smart card, certifikát. Může být ztracen.
👤ARE Otisk prstu, Face ID, iris, hlas. Nelze změnit při kompromitaci!

Bonusové faktory: Somewhere you ARE (GPS, IP), Something you DO (typing pattern, gait analysis).

02

Password-based authentication

Nejstarší metoda. Username + password → systém porovná s uloženým hashem. Jednoduché, ale slabé bez správné implementace.

Slabá hesla ❌

"password123" (slovníkové), "qwerty" (keyboard pattern), "JanNovak1990" (osobní info). Krátká, předvídatelná.

Silná hesla ✅

Min. 12+ znaků, mix velkých/malých/číslic/symbolů, unikátní per účet. Passphrase: "c0rrect-h0rse-b@ttery-st@ple"

Password Manager = řešení!

Bezpečně ukládá všechna hesla šifrovaně. Stačí 1 master password. Generuje náhodná silná hesla. Auto-fill. Příklady: 1Password, Bitwarden, KeePass.

Útoky na hesla
  • Brute Force: Všechny kombinace. Dictionary: Slovníková slova
  • Rainbow Table: Precomputed hashe (obrana: salt!)
  • Credential Stuffing: Ukradené credentials z jiného breache
  • Phishing: Social engineering. Keylogging: Malware

Obrana: bcrypt/Argon2 + salt, rate limiting, CAPTCHA, breach notification, MFA.

MFA Fatigue Attack

Útočník má heslo → spamuje push notifikace dokud omylem neschválíš. Obrana: Number matching – musíš zadat číslo z webu do app.

04

Biometrická autentizace

Unikátní fyzické nebo behaviorální charakteristiky. Nelze zapomenout, ale při kompromitaci NELZE změnit!

Fingerprint 👆

Nejpoužívanější. Smartphone, laptop. Rychlé. Zranitelnost: fake prst (gummy bear attack).

Face Recognition 🤳

Face ID, Windows Hello. 3D senzory bezpečnější (nelze oklamat fotkou). Zranitelnost: dvojčata.

Iris/Retina 👁️

Extrémně přesné. High-security prostředí. Drahé senzory.

Voice + Behavioral 🗣️

Hlas, typing pattern, gait. Continuous auth. Zranitelnost: nahrávka hlasu.

Best practice: Biometrika VŽDY kombinovat s jiným faktorem (MFA). Nikdy nespoléhat jen na biometriku! Při kompromitaci nelze změnit otisk prstu.

05

Token-based authentication

Po přihlášení dostaneš TOKEN (kryptograficky podepsaný string). S každým requestem posíláš token místo credentials.

JWT (JSON Web Token) – nejpoužívanější

Header.Payload.Signature

  • Header: Typ (JWT) + signing algoritmus
  • Payload: Data (user ID, role, expiration)
  • Signature: Kryptografický podpis (ověřuje nezměněnost)

Access Token (15 min – 1 h) pro requesty. Refresh Token (dny–měsíce) pro nový access token.

OAuth 2.0 – „Sign in with Google"

Klikneš „Sign in with Google" → Google: „App XYZ chce přístup. Povolit?" → Schválíš → Google pošle token → App přistupuje k datům BEZ tvého hesla!

06

Certificate-based authentication

X.509 certifikáty místo hesel

Uživatel má certifikát (.p12/.pfx) s private key (na PC nebo smart card). Server ověří: důvěryhodná CA? Platný? Nerevokován? Klient podepíše challenge private key → server ověří.

Použití: Smart cards, VPN, S/MIME email, code signing, SSL client certs, vojenství. Mutual TLS (mTLS): Obě strany certifikát → vzájemné ověření.

Single Sign-On (SSO)

Přihlásíš se JEDNOU → přístup k VÍCE aplikacím bez opakovaného přihlašování.

🔐 Identity Provider

💬 Slack
☁️ AWS
1 přihlášení → přístup ke všem apps. Žádné opakované zadávání hesla.
SSO protokoly
  • SAML: XML-based, enterprise standard. SAML assertion s identitou. Okta, Azure AD
  • OpenID Connect (OIDC): Na OAuth 2.0, JSON/JWT. Modernější. „Sign in with Google"
  • Kerberos: Ticket-based (Active Directory). TGT → service tickets

Riziko: Single point of failure + single point of attack. Kompromitace SSO = přístup ke VŠEM apps. SSO MUSÍ být kombinováno s MFA!

08

Autentizační protokoly

LDAPDIRECTORY SERVICE

Protokol pro přístup k directory (hierarchická DB uživatelů). App pošle username+password → LDAP server hledá → bind operace → Success/Fail. Active Directory je na LDAP. OpenLDAP = open-source.

PAPPLAIN TEXT – NEBEZPEČNÉ!

Username + password posílány v PLAIN TEXT. Žádná ochrana proti sniffing/replay. Jen přes zabezpečený kanál (VPN, TLS).

CHAPCHALLENGE-RESPONSE

Heslo NIKDY nejde přes síť! Server pošle challenge → klient: hash = MD5(challenge + password) → pošle hash. Server porovná. Ochrana proti replay (challenge vždy jiný).

EAPFRAMEWORK

Framework pro různé autentizační metody (ne jeden protokol). Zapojíš různé mechanismy:

  • EAP-TLS: Mutual certifikáty – nejbezpečnější
  • EAP-TTLS: TLS tunnel + password uvnitř
  • PEAP: TLS tunnel + password (Microsoft, Wi-Fi WPA2-Enterprise)
SSL/TLSMUTUAL AUTH

Normální TLS: jen server cert. Mutual TLS (mTLS): Obě strany certifikáty → vzájemné ověření. API auth, microservices, Zero Trust.

09

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

TŘI FAKTORY

  • KNOW (heslo, PIN), HAVE (telefon, YubiKey), ARE (otisk, Face ID). MFA = 2+ faktorů z RŮZNÝCH kategorií
  • MFA blokuje 99.9 % automatizovaných útoků. SMS 2FA < TOTP < Hardware token

METODY AUTENTIZACE

  • Hesla: Min 12+ znaků, unikátní, password manager. bcrypt/Argon2 + salt. 81 % breaches = slabá hesla
  • Biometrie: Fingerprint, Face ID, iris, voice. Nelze změnit při kompromitaci → vždy + MFA
  • Tokeny (JWT): Header.Payload.Signature. Access (krátký) + Refresh (dlouhý). OAuth 2.0 = „Sign in with Google"
  • Certifikáty: X.509, PKI. Smart cards, VPN. Mutual TLS (mTLS). Nejbezpečnější ale komplexní
  • SSO: 1 přihlášení → všechny apps. SAML (XML), OIDC (JSON/JWT), Kerberos (tickets). MUSÍ + MFA!

PROTOKOLY

  • LDAP: Directory service (Active Directory). Centrální DB uživatelů
  • PAP: Plain text heslo – NEBEZPEČNÉ! Jen přes VPN/TLS
  • CHAP: Challenge-response, heslo nikdy na síti. hash(challenge + password)
  • EAP: Framework pro Wi-Fi Enterprise. EAP-TLS (certifikáty, nejbezpečnější), PEAP (TLS tunnel + password)
  • mTLS: Mutual TLS – obě strany certifikáty. Zero Trust, microservices

TREND

  • Passwordless = budoucnost (FIDO2/WebAuthn: biometrika + HW token, žádná hesla)
  • Zero Trust: „Never trust, always verify" – kontinuální autentizace (device, lokace, risk score)
