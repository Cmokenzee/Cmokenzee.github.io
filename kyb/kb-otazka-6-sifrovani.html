Symetrická kryptografie

Stejný klíč pro šifrování i dešifrování. Rychlá, efektivní pro velké objemy dat.

Výhody

Velmi rychlá. Efektivní pro velká data. Jednodušší implementace.

Nevýhody

Key distribution problem – jak bezpečně sdílet klíč? Škálovabilita: N uživatelů = N(N−1)/2 klíčů. Žádné non-repudiation.

Algoritmy
  • AES (128/192/256-bit): Nejpoužívanější. WPA2/3, VPN, BitLocker. Standard od 2001
  • DES (56-bit): Zastaralé, NEZABEZPEČENÉ (brute force). Nahrazeno 3DES → AES
  • ChaCha20: Moderní stream cipher. Rychlý na mobilech. Chrome, WireGuard

Asymetrická kryptografie

Dva klíče: PUBLIC KEY (veřejný, sdílíš) + PRIVATE KEY (soukromý, tajný). Co zašifruješ jedním, dešifruješ druhým.

Algoritmy
  • RSA (2048–4096-bit): Nejpoužívanější. Faktorizace prvočísel. SSL/TLS, SSH, PGP
  • ECC (256-bit): Kratší klíče = stejná bezpečnost (256-bit ECC ≈ 3072-bit RSA). Bitcoin, moderní TLS
  • Diffie-Hellman: Key exchange protocol (ne šifrování!). Sdílený klíč přes nezabezpečený kanál. TLS, IPsec

Best of both worlds – tohle dělá HTTPS!

04

Hashování

Jednosměrná funkce: vstup libovolné délky → výstup fixní délky. Nelze zpětně dešifrovat!

"Ahoj" → SHA-256 → 3c59dc048e8850243be8079a5c74d079...
"Ahoj!" → SHA-256 → 8f4e33f3dc3e414ff94e5fb6905cba8c... ← úplně jiný! (avalanche)
Vlastnosti hash funkce
  • Deterministická: Stejný vstup → vždy stejný hash
  • Jednosměrná: Z hashe nelze získat původní data
  • Fixní délka: 1 byte nebo 1 GB → hash stejně dlouhý
  • Avalanche effect: Změna 1 bitu → změní 50 % hashe
  • Collision resistant: Extrémně těžké najít 2 vstupy se stejným hashem
Algoritmy
  • SHA-256: 256-bit, bezpečný, široce používaný (Bitcoin, TLS, podpisy)
  • SHA-1 (160-bit): DEPRECATED – kolize nalezeny 2017
  • MD5 (128-bit): NEZABEZPEČENÝ – jen pro checksums, NE bezpečnost
  • bcrypt / Argon2: Pro HESLA – záměrně pomalé + salt (ochrana proti brute force)
Použití + Salting

Hesla: DB ukládá hash, ne plaintext. Integrita: Checksums stažených souborů. Podpisy: Podepisuje se hash (rychlejší). Blockchain: Hash předchozího bloku → řetězec.

Salt = náhodná data přidaná k heslu před hashováním. 2 uživatelé se stejným heslem → různé hashe. Ochrana proti rainbow table útokům.

05

Certifikáty a CA

Digitální certifikát (X.509) = elektronický dokument vázající PUBLIC KEY k identitě. Jako „digitální občanský průkaz".

Co obsahuje certifikát

Public Key majitele. Identita (doména, organizace). Issuer (kdo vydal – CA). Sériové číslo. Platnost (1–2 roky). Digitální podpis CA.

Chain of Trust

🏛️ Root CA
Předinstalovaná v prohlížeči (DigiCert, Let's Encrypt)
↓ podepisuje
📋 Intermediate CA
↓ podepisuje
🔒 End-entity certifikát (google.com)
Typy certifikátů + CRL/OCSP
  • DV: Domain Validated – jen ověření domény (základní)
  • OV: Organization Validated – CA zkontroluje firmu
  • EV: Extended Validation – nejvyšší level (zelený proužek s názvem)

CRL = seznam zrušených certifikátů. OCSP = real-time ověření platnosti. Důvod: private key mohl být ukraden → certifikát musí být okamžitě zrušen.

Co zajišťuje
  • Autentizace: Dokument je od Alice (jen ona má private key)
  • Integrita: Nebyl změněn (hash by nesouhlasil)
  • Non-repudiation: Alice nemůže popřít podpis

Použití: DocuSign, code signing, S/MIME email, e-banking, datové schránky.

08

SSL/TLS – implementace

TLS (Transport Layer Security) = protokol pro zabezpečení komunikace přes internet. HTTPS = HTTP + TLS. Aktuálně: TLS 1.3 (2018).

TLS Handshake – krok za krokem (https://google.com)
1→
Client Hello
Prohlížeč: „Podporuju TLS 1.3, 1.2. Můj random number XYZ. Cipher suites…"
2←
Server Hello + Certificate
Server: „OK, TLS 1.3. Cipher: AES_256_GCM_SHA384." Pošle SSL certifikát (public key).
3✓
Certificate Verify
Prohlížeč ověří certifikát: platnost, doména, podpis CA (vestavěná v browseru).
4↔
Key Exchange (ECDHE)
Obě strany vytvoří sdílený session key (pro AES). Nikdo jiný ho nezná. Perfect Forward Secrecy!
5✓
Finished
Oba pošlou „Finished" zašifrovanou session key. Handshake OK.
6↔
Secure Communication
Veškerá komunikace AES šifrovaná se session key. Rychlé + bezpečné.
Perfect Forward Secrecy (PFS)

ECDHE zajišťuje unikátní klíč pro KAŽDOU session. I když někdo v budoucnu ukradne private key serveru, nemůže dešifrovat staré zachycené komunikace. Každá session je nezávislá.

09

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

SYMETRICKÁ vs ASYMETRICKÁ

  • Symetrická: 1 klíč, rychlá, pro data. AES (128/256-bit), ChaCha20. Problém: distribuce klíče
  • Asymetrická: 2 klíče (public+private), pomalá, pro klíče+podpisy. RSA (2048+), ECC (256). Non-repudiation
  • Hybridní (HTTPS): Asymetrická pro výměnu klíče → symetrická pro data = best of both

HASH

  • Jednosměrná, fixní délka, avalanche effect, collision resistant. NELZE dešifrovat!
  • SHA-256 (bezpečný), SHA-1 (deprecated), MD5 (broken). bcrypt/Argon2 pro hesla (+salt)
  • Použití: hesla, checksums, digitální podpisy, blockchain

CERTIFIKÁTY & PODPIS

  • Certifikát (X.509): Váže public key k identitě. Vydává CA (DigiCert, Let's Encrypt). Chain of Trust: Root → Intermediate → End-entity
  • Digitální podpis: Hash dokumentu + šifrování PRIVATE KEY. Zajišťuje: autentizace + integrita + non-repudiation

VPN & TLS

  • VPN: Šifrovaný tunnel. OpenVPN (SSL/TLS), WireGuard (moderní, rychlý), IPsec (site-to-site). PPTP = broken!
  • TLS Handshake: Client Hello → Server Hello + Cert → Verify → ECDHE key exchange → AES session
  • PFS: Unikátní session key → krádež private key neodhalí staré komunikace
  • TLS 1.3 (aktuální), TLS 1.0/1.1 deprecated. HTTPS = HTTP + TLS = zelený zámek
