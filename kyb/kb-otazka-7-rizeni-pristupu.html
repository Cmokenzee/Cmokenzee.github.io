01

Co je řízení přístupu

Access Control = KDO (Subject) má přístup KE KTERÝM zdrojům (Object) a JAKÉ operace (Action) může provádět.

Tři komponenty + AAA
  • Subject: Uživatel, proces, program
  • Object: Soubor, databáze, server
  • Action: Read, write, execute, delete

AAA: Authentication (kdo jsi?) → Authorization (co smíš? = řízení přístupu) → Accounting (co jsi dělal?)

02

DAC (Discretionary Access Control)

👤DACVLASTNÍK ROZHODUJE

Vlastník zdroje sám rozhoduje kdo má přístup. Nejběžnější model v běžných OS (Windows, Linux).

Příklad: Vytvoříš Budget.xlsx → Properties → Security → Jan (Read/Write), Eva (Read).

Linux permissions příklad
-rw-r--r-- 1 alice staff budget.txt
alice (owner): read+write | staff (group): read | others: read

Výhody

Flexibilní, jednoduché, user-friendly. Vlastník má plnou kontrolu.

Nevýhody

Rozptýlená správa. Obtížný audit. Riziko human error. Data leakage. Trojan horse → tvoje práva.

Použití: Windows NTFS, Linux chmod/chown, Google Drive/OneDrive sdílení.

03

MAC (Mandatory Access Control)

🏛️MACCENTRÁLNÍ POLITIKA

Přístup řízen centrálně podle bezpečnostních politik. Uživatel NEMŮŽE měnit práva. Clearance ≥ Classification → povoleno.

🔴 TOP SECRET
🟠 SECRET
🟡 CONFIDENTIAL
🟢 UNCLASSIFIED

Major (Secret clearance) → čte Unclassified + Confidential + Secret. NEČTE Top Secret.

Výhody

Škálovatelné (tisíce uživatelů). Konzistentní práva. Snadný onboarding/offboarding. Audit-friendly. Least Privilege.

Nevýhody

Role explosion (stovky rolí). Nedostatečná granularita. Statické (ne dynamické). Nutná pravidelná revize.

Použití: Active Directory Groups, AWS IAM Roles, SQL Server roles, Salesforce, většina enterprise apps.

05

Rule-Based Access Control

📋Rule-BasedIF-THEN PRAVIDLA

Přístup řízen na základě pravidel (IF-THEN). Založeno na kontextu: čas, lokace, zařízení, stav systému. Často kombinováno s RBAC.

IF time = Mon-Fri 9:00-17:00 THEN allow ELSE deny
IF location = office (10.0.0.0/8) THEN allow ELSE require VPN
IF failed_logins > 3 THEN lock 30 min
Role-Based vs Rule-Based

ROLE-Based: Založeno na IDENTITĚ a ROLI (kdo jsi). RULE-Based: Založeno na PODMÍNKÁCH a KONTEXTU (kdy, kde, jak).

Často kombinovány: Jan má roli Developer (RBAC) + může přistupovat jen z office v pracovní době (Rule-based).

Použití: Firewall rules, Router ACLs, IDS/IPS, Microsoft 365 Conditional Access, DLP policies.

06

ACL (Access Control Lists)

📄ACLSEZNAM NA OBJEKTU

Seznam specifikující KDO má JAKÝ přístup k danému objektu. Připojený k objektu (ne k uživateli). Obsahuje ACE (Access Control Entries).

-- Soubor: Budget_2024.xlsx --
ALLOW Alice — Full Control
ALLOW Finance Group — Read, Write
ALLOW Everyone — Read
DENY Bob — (explicitní zákaz)
Pořadí ACE je KRITICKÉ!

Špatně: 1. Everyone=Read, 2. Bob=Deny → Bob má přístup! (Everyone match první)

Správně: 1. Bob=Deny, 2. Everyone=Read → Bob zamítnut. DENY má přednost. Systém aplikuje PRVNÍ match.

Typy: Filesystem ACL (Windows NTFS, Linux ext4) a Network ACL (Router/Firewall – permit/deny IP, port, protocol). Inheritance: Podřízenécí dědí ACL od nadřazené složky.

07

ABAC (Attribute-Based Access Control)

🧩ABACNEJFLEXIBILNĚJŠÍ / MODERNÍ

Přístup řízen na základě atributů subjektu, objektu, prostředí a akce. Nejmodernější model. Dynamické politiky.

4 typy atributů
KategoriePříklady
Subject (kdo)Role, Department, Clearance, Job Title, Citizenship
Object (co)Classification, Type, Owner, Tags
Environment (kontext)Time, Location, Network Type, Device, Threat Level
Action (jak)Read, Write, Execute, Delete, Share
ALLOW IF:
  Subject.Department = "Finance" AND
  Object.Type = "Financial Report" AND
  Action = "Read" AND
  Environment.Time = Mon-Fri 9:00-17:00 AND
  Environment.Network = "Corporate" OR "VPN"

Použití: AWS IAM Policies, Azure AD Conditional Access, healthcare (HIPAA), banking (PCI DSS), Zero Trust architektury. Standard: XACML (XML-based).

10

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

MODELY

  • DAC: Vlastník rozhoduje. Windows/Linux permissions, Google Drive. Flexibilní ale riziko leakage
  • MAC: Centrální politika, clearance ≥ classification. Bell-LaPadula (no read up, no write down = confidentiality), Biba (opačně = integrity). Vojenství, SELinux
  • RBAC: Práva přiřazena rolím ne uživatelům. Nejpoužívanější enterprise. AD Groups, AWS IAM. Škálovatelné, audit-friendly
  • Rule-Based: IF-THEN pravidla (čas, lokace, zařízení). Firewall rules, Conditional Access. Kontextově aware
  • ACL: Seznam na OBJEKTU (ne uživateli). ACE entries: allow/deny. Pořadí kritické! Deny má přednost. Filesystem + network ACLs
  • ABAC: 4 atributy (Subject/Object/Environment/Action). Nejflexibilnější, nejmodernější. AWS IAM, Zero Trust. XACML standard

BEST PRACTICES

  • Least Privilege – minimální nutná práva. Separation of Duties – 2+ osoby pro kritické operace
  • Default Deny – vše zamítnuto, explicitně povoluj. Regular Reviews – quarterly revize
  • JIT Access – dočasný elevated přístup. Defense in Depth – kombinuj modely (RBAC + Rule + MFA)

KDY CO POUŽÍT

  • Personal / malé týmy: DAC. Vojenství: MAC. Enterprise: RBAC
  • Network security: Rule-Based + ACL. Cloud / Zero Trust: ABAC
  • V praxi se kombinují (hybridní přístup). Trend → ABAC + kontextově-aware řízení
