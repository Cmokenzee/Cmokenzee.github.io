01

Úvod do aplikační vrstvy

Aplikační vrstva je nejvyšší vrstva TCP/IP modelu. Poskytuje síťové služby přímo uživatelským aplikacím. V OSI odpovídá vrstvám L5+L6+L7 (Session + Presentation + Application).

Porty – adresování aplikací

Každý aplikační protokol používá TCP nebo UDP port (16-bit, 0–65535).

  • Well-known (0–1023) – HTTP 80, HTTPS 443, SSH 22, FTP 21, SMTP 25, DNS 53
  • Registered (1024–49151) – registrované aplikace
  • Dynamic/Private (49152–65535) – dočasné (ephemeral)
02

Klient-Server model

Centralizovaný model. Server poskytuje služby (always-on, stálá IP), klienti je konzumují (připojují se podle potřeby). Klienti nekomunikují přímo mezi sebou.

Výhody

Centrální správa (data, zálohy). Bezpečnost (auth, ACL). Konzistence dat. Škálovatelnost upgradem serveru.

Nevýhody

Single Point of Failure – server padne → všichni bez služby. Bottleneck při přetížení. Drahý HW a údržba.

Příklady

Web (prohlížeč ↔ Apache/Nginx), Email (Outlook ↔ Exchange), Databáze (app ↔ MySQL), Soubory (PC ↔ file server), DNS (resolver ↔ DNS server)

03

P2P (Peer-to-Peer) model

Decentralizovaný model. Žádný centrální server. Každý peer je současně klient i server. Přímá komunikace peer ↔ peer, dynamická topologie.

Výhody

Žádný single point of failure. Více peerů = více zdrojů. Nízké náklady. Censorship resistant.

Nevýhody

Těžká správa, žádná centrální kontrola. Bezpečnost (důvěra?). Konzistence dat. Výkon závisí na peerech.

Typy P2P

Pure P2P

Žádný centrální koordinátor. Peery si najdou sami (flooding, DHT). Příklad: Gnutella.

Hybrid P2P

Centrální server pro indexování/hledání, přenos dat P2P. Příklad: BitTorrent s trackerem.

Structured (DHT)

Distributed Hash Table – každý peer zodpovědný za část keyspace. Příklad: BitTorrent DHT, Kademlia.

Příklady P2P

BitTorrent (file sharing), Bitcoin/Ethereum (blockchain), IPFS (decentralizovaný storage), Tor (anonymní browsing)

HTTP a HTTPS

HTTP (HyperText Transfer Protocol)

Protokol pro přenos webových stránek. Základ World Wide Web.

Vlastnosti HTTP
  • Port: TCP 80 (HTTP), TCP 443 (HTTPS)
  • Stateless – server si nepamatuje předchozí requesty
  • Request-Response model, text-based protokol

HTTPS (HTTP Secure)

HTTP + TLS/SSL šifrování. Port TCP 443. Chrání důvěrnost (encryption), integritu (tampering detection), autentizaci (certifikáty).

05

Webservery

Apache

Open-source (1995). Modulární (.htaccess). Process-based (MPM prefork/worker). ~30 % webů.

Nginx

Event-driven, asynchronní. Vyšší výkon (static content, reverse proxy). Nižší RAM. ~35 % webů, nejpopulárnější.

IIS

Microsoft Windows Server. Integrace s .NET, ASP.NET. GUI správa.

06

FTP, TFTP, SFTP

FTP (File Transfer Protocol)

Přenos souborů mezi klientem a serverem. Upload, download, directory listing.

Dvě spojení!
  • Control connection – TCP port 21 (příkazy: USER, PASS, LIST, RETR, STOR)
  • Data connection – TCP port 20 (přenos souborů)

POZOR Klasické FTP je nešifrované – hesla i data plaintext!

Active mode

Server iniciuje data connection zpět ke klientovi. Problém s NAT/firewall (klient za NAT).

Passive mode (PASV)

Klient iniciuje obě spojení. Řeší NAT. Běžnější dnes. Server sdělí port pro data.

Bezpečné alternativy

ProtokolPortPopis
FTPS990 / 21FTP + TLS/SSL šifrování (implicit / explicit STARTTLS)
SFTP22NENÍ FTP! Běží přes SSH. Jedno spojení. Šifrované. Bezpečnější.
SCP22Secure Copy přes SSH. Jednoduchý přenos souborů.

TFTP (Trivial File Transfer Protocol)

Velmi jednoduchý protokol
  • Port: UDP 69 (connectionless)
  • Žádná autentizace, žádný directory listing
  • Lock-step: pošli block (512 B) → čekej ACK → další block
  • Použití: PXE boot, firmware update Cisco, IP telefony
07

SMB a NFS

SMB (Server Message Block)

Port TCP 445. Windows file sharing, tiskárny. UNC cesta: \\server\share. Verze: SMB1 (unsafe!), SMB2, SMB3 (šifrování). Auth: NTLM, Kerberos. Linux: Samba.

NFS (Network File System)

Port TCP/UDP 2049. Unix/Linux sdílení souborů. Mount vzdáleného FS jako lokální. NFSv3 (stateless), NFSv4 (stateful). Použití: NAS, datacentra, home dirs.

08

Telnet a SSH

NEBEZPEČNÉ Telnet

Port TCP 23. Vzdálený terminál. Vše plaintext – hesla viditelná! Man-in-the-Middle triviální. Nahrazeno SSH. Jediné použití dnes: testování TCP (telnet host 80).

BEZPEČNÉ SSH

Port TCP 22. Šifrovaný tunel (AES, ChaCha20). Autentizace: heslo nebo public-key (lepší!). SSH-2 = aktuální verze.

  • SFTP – SSH File Transfer Protocol (ne FTP!)
  • Port forwarding (tunneling) – SSH tunel pro jiné protokoly
  • X11 forwarding – vzdálené GUI aplikace
09

NTP (Network Time Protocol)

Synchronizace času v síti
  • Port: UDP 123
  • Hierarchie stratum: 0 (atomic clock) → 1 (sync ze stratum 0) → 2 → 3 …
  • Přesnost: sub-milisekundy LAN, ~10 ms WAN
  • Servery: pool.ntp.org, time.google.com
  • Použití: OS, servery, routery, security logy (korelace událostí)
10

Email protokoly

Komponenty email systému
  • MUA (Mail User Agent) – email klient (Outlook, Thunderbird, Gmail web)
  • MTA (Mail Transfer Agent) – mail server, přenáší mezi servery
  • MDA (Mail Delivery Agent) – doručuje do mailboxu

SMTP (Simple Mail Transfer Protocol)

Odesílání emailů. MUA → MTA, MTA → MTA. Push protokol, text-based.

SMTP porty
  • Port 25 – server ↔ server (relay)
  • Port 587 – klient → server (submission, STARTTLS)
  • Port 465 – SMTPS (deprecated)

POP3 vs. IMAP

POP3 (Post Office Protocol v3)

Port 110 / 995 (SSL). Download-and-delete. Emaily lokálně, smaže ze serveru. Offline přístup. Žádná synchronizace mezi zařízeními. Jednoduché – 1 zařízení.

IMAP (Internet Message Access Protocol)

Port 143 / 993 (SSL). Emaily zůstávají na serveru. Synchronizace mezi zařízeními. Složky (INBOX, Sent, Trash). Partial fetch, search na serveru. MODERNÍ standard.

Cesta emailu od zdroje k cíli

Scénář: Alice (alice@company.com) posílá email Bobovi (bob@example.org).

Alice MUA → SMTP :587 → DNS MX → SMTP :25 → MDA → IMAP :993 → Bob MUA
Podrobný průchod
1
Alice napíše email v MUA (Outlook), klikne Send
2
MUA → smtp.company.com:587
STARTTLS šifrování, autentizace, SMTP příkazy (MAIL FROM, RCPT TO, DATA)
3
SMTP server: DNS dotaz na MX record
„Který mail server obsluhuje example.org?" → mx1.example.org (priority 10)
4
SMTP relay: company.com → mx1.example.org:25
Server-to-server SMTP konverzace. Každý MTA přidá Received: header.
5
MDA doručí do Bobova mailboxu
Spam/virus filtry, uložení do databáze/souboru.
6
Bob otevře MUA → IMAP imap.example.org:993
Autentizace, SELECT INBOX, stáhne nový email.
Received headers

Každý MTA přidá Received: header s timestampem. Čtení zdola nahoru = cesta emailu. Slouží k debuggingu – kde se email zasekl.

12

Zabezpečení emailu

SPF

Sender Policy Framework. DNS TXT record – které IP adresy mohou odesílat za doménu. Ochrana proti spoofingu.

DKIM

DomainKeys Identified Mail. Kryptografický podpis emailu. Public key v DNS, private key na mail serveru. Ověří, že email nebyl změněn.

DMARC

Domain-based Message Authentication. Policy pro emaily které selžou SPF/DKIM. DNS TXT record. Quarantine nebo reject podezřelé.

13

Shrnutí klíčových bodů

Na zkoušku si zapamatuj
  • Klient-Server = centrální, single point of failure. P2P = decentralizovaný, odolné, peer=klient+server
  • HTTP = stateless, port 80, GET/POST/PUT/DELETE. Kódy: 2xx OK, 3xx redirect, 4xx client error, 5xx server error
  • HTTPS = HTTP + TLS, port 443. TLS handshake → symetrické šifrování (AES). Certifikáty X.509
  • HTTP/2 = binary, multiplexing. HTTP/3 = QUIC (UDP)
  • Nginx = event-driven, nejpopulárnější webserver (~35 %)
  • FTP = DVĚ spojení! Port 21 (control) + 20 (data). Passive mode řeší NAT. Nešifrované!
  • SFTP = přes SSH (port 22), NENÍ FTP. FTPS = FTP + TLS
  • TFTP = UDP 69, žádná auth, 512 B blocky, PXE boot, firmware update
  • SMB = port 445, Windows sharing. NFS = port 2049, Linux/Unix
  • Telnet = port 23, plaintext, NEBEZPEČNÉ! → nahrazeno SSH (port 22, šifrované, public-key auth)
  • NTP = UDP 123, synchronizace času, stratum hierarchie
  • SMTP = port 587 (submission) / 25 (relay), odesílání emailů
  • POP3 = port 110/995, download-delete, 1 zařízení
  • IMAP = port 143/993, emaily na serveru, multi-device sync, MODERNÍ
  • Cesta emailu: MUA → SMTP :587 → DNS MX → SMTP :25 relay → MDA → IMAP :993 → MUA
  • Email security: SPF (kdo smí odesílat), DKIM (podpis), DMARC (policy pro neplatné)
