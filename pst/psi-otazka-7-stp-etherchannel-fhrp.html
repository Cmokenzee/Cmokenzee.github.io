01

Redundance a problém smyček

Cíl: síť dostupná 24/7 i při výpadku. Řešení = redundance – záložní cesty a zařízení. Ale redundance na L2 vytváří smyčky!

Tři problémy L2 smyček

Broadcast Storm

Frame cirkuluje donekonečna a multiplikuje se (2→4→8→16…). Síť se během sekund zhroutí – 100% CPU, network meltdown.

Duplicitní Frames

Frame jde dvěma cestami → PC přijme stejný frame 2×. Může způsobit chyby aplikací (např. duplicitní DB zápisy).

Nestabilní MAC tabulka

MAC adresa osciluje mezi porty (port 1 → port 2 → port 1…). Switch neví kam forwardovat → flooding na všechny porty.

Řešení: STP

Spanning Tree Protocol blokuje redundantní porty → vytvoří logickou strom topologii BEZ smyček, ale zachová fyzickou redundanci. Pokud aktivní cesta selže → STP odblokuje záložní port.

03

STP algoritmus (STA) – výpočet

Spanning Tree Algorithm ve 4 krocích:

Krok 1 – Volba Root Bridge

Switch s nejnižší Bridge ID (BID) = Root Bridge.

BID = Priority (2 B, default 32768) + MAC adresa (6 B). Stejná priority → rozhodne nižší MAC.

Priority musí být násobek 4096. Konfigurace: spanning-tree vlan 1 priority 4096

Krok 2 – Root Porty (na non-root switchech)

Root Port (RP) = port s nejnižší cost k Root Bridge. Každý non-root switch má právě jeden RP. Vždy ve stavu Forwarding.

Tie-breaker: 1) nejnižší sender BID → 2) nejnižší sender Port ID → 3) nejnižší receiver Port ID

Krok 3 – Designated Porty

Designated Port (DP) = port který forwarduje provoz pro daný segment. Každý segment má právě jeden DP. Na Root Bridge jsou všechny porty designated. Vždy Forwarding.

Volba: switch s nejnižší cost k Root. Stejný cost → nižší BID.

Krok 4 – Blokování

Port který není Root Port ani Designated Port → BLOCKING. Neforwarduje data → eliminuje smyčky!

Příklad kompletního výpočtu

Topologie: Switch A (BID 4096) ↔ Switch B (BID 32768) ↔ Switch C (BID 32768). Switch A ↔ Switch C (druhý link).

1
Root Bridge = Switch A (nejnižší BID 4096)
2
Root Porty: Switch B port k A (cost 4), Switch C port k A (cost 4)
3
Designated Porty: Segment A–B a A–C = Switch A (Root). Segment B–C = Switch B (nižší port ID)
4
Switch C port do Switch B = BLOCKING → smyčka eliminována!

Druhy STP protokolů

ProtokolStandardKonvergenceVlastnosti

RSTP – nové port roles a states
  • Port roles: Root, Designated, Alternate (záloha k Root Port), Backup (záloha k Designated)
  • Port states: Discarding (= Blocking + Listening), Learning, Forwarding
  • Proposal/Agreement handshake → velmi rychlý přechod do Forwarding
05

STP rozšíření

PortFast

Port okamžitě do Forwarding (bez 30 s čekání). Pouze na access porty k PC! NIKDY na trunk/inter-switch porty.

spanning-tree portfast

BPDU Guard

Pokud PortFast port přijme BPDU → port se vypne (err-disabled). Ochrana proti nechtěnému připojení switche.

spanning-tree bpduguard enable

Root Guard

Pokud port přijme superior BPDU (nižší BID) → root-inconsistent state. Zabrání nechtěné změně Root Bridge.

Loop Guard

Pokud blocking port přestane přijímat BPDU → loop-inconsistent (zůstane blokován). Ochrana proti ztrátě BPDU.

Konfigurace priority a Root Bridge
! Nastavení priority (musí být násobek 4096)
spanning-tree vlan 1 priority 4096

! Nebo makro pro Root
spanning-tree vlan 1 root primary ! priority 24576 nebo nižší
spanning-tree vlan 1 root secondary ! priority 28672

! Verify
show spanning-tree
show spanning-tree vlan 1

EtherChannel – agregace linky

Problém

4 Gigabit linky mezi switchi → ale STP zablokuje 3 (redundance) → využiješ jen 1 Gbps místo 4 Gbps!

Řešení: EtherChannel (Port Channel)

Seskupení více fyzických linků do jednoho logického linku. STP vidí EtherChannel jako 1 link → neblokuje! Všechny linky aktivní → součet bandwidth.

Switch A
Po1
4 Gbps
Switch B
Výhody EtherChannel
  • N linků = N× bandwidth (4 × 1 Gbps = 4 Gbps)
  • Redundance – pokud 1 link selže, ostatní fungují (3 Gbps)
  • STP neblokuje – vidí jako 1 link
  • Žádná STP re-konvergence při výpadku 1 fyzického linku
  • Load balancing – provoz distribuován mezi linky
Požadavky – všechny linky MUSÍ být identické!
  • Stejná rychlost (speed) a duplex
  • Všechny access NEBO všechny trunk (nelze mix)
  • Stejná VLAN (access) / stejné allowed VLANs + native VLAN (trunk)

Nesplněno → EtherChannel nebude fungovat (err-disabled / suspended)!

Load Balancing algoritmy

Provoz distribuován hashovacím algoritmem. Konfigurace: port-channel load-balance <method>

  • src-mac, dst-mac, src-dst-mac (výchozí)
  • src-ip, dst-ip, src-dst-ip

FHRP – redundance gateway

Problém

PC má default gateway = IP routeru. Pokud router selže → PC ztratí konektivitu ven ze sítě!

Řešení: FHRP (First Hop Redundancy Protocol)

Dva+ routery sdílí virtuální IP (VIP). PC má gateway = VIP. Jeden router = Active, druhý = Standby. Pokud Active selže → Standby okamžitě převezme VIP → konektivita zachována!

Jak to funguje
1
Router 1 (192.168.1.2) + Router 2 (192.168.1.3) → VIP 192.168.1.1
2
PC má gateway = 192.168.1.1 (VIP)
3
Router 1 = Active → forwarduje provoz, Router 2 = Standby → monitoruje
4
Router 1 selže (3× hello timeout) → Router 2 převezme VIP
PC neví o výpadku → žádná změna konfigurace, failover < 3 s

HSRP (Cisco)

Hot Standby Router Protocol. 1 Active, 1 Standby. Preempt OFF default → vrácený router se nestane Active (musíš standby preempt). Jen Cisco.

VRRP (Standard)

Virtual Router Redundancy Protocol. 1 Master, N Backup. Preempt ON default → vyšší priority převezme okamžitě. Multi-vendor.

GLBP (Cisco)

Gateway Load Balancing Protocol. Jediný s load balancing! Až 4 AVF forwardují současně. Round-robin / Weighted / Host-dependent. Využití všech routerů.

Konfigurace FHRP (Cisco)
! HSRP
interface GigabitEthernet0/0
standby 1 ip 192.168.1.1 ! VIP
standby 1 priority 110 ! vyšší = preferovaný
standby 1 preempt ! povolení preemption
standby 1 timers 1 3 ! hello 1s, hold 3s

! VRRP
vrrp 1 ip 192.168.1.1
vrrp 1 priority 110

! GLBP
glbp 1 ip 192.168.1.1
glbp 1 priority 110
glbp 1 load-balancing round-robin

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

REDUNDANCE A SMYČKY

  • Redundance na L2 vytváří smyčky → broadcast storm, duplicitní frames, nestabilní MAC tabulka
  • Řešení: STP blokuje redundantní porty → strom topologie bez smyček

STP (SPANNING TREE)

  • STA: 1) Root Bridge (nejnižší BID) → 2) Root Porty (nejnižší cost) → 3) Designated Porty → 4) Blokování
  • BID = Priority (default 32768, násobek 4096) + MAC. Cost: 10M=100, 100M=19, 1G=4, 10G=2
  • Konvergence: STP = 50 s (pomalé!), RSTP = ~6 s (rychlé)
  • Rapid PVST+ = per-VLAN + rapid → nejpoužívanější (default Cisco)
  • PortFast = okamžitě Forwarding, POUZE access porty k PC!
  • BPDU Guard = vypne port při přijetí BPDU (ochrana PortFast portů)

ETHERCHANNEL

  • Více linků jako 1 logický → STP neblokuje, N× bandwidth, redundance
  • Protokoly: PAgP (Cisco, desirable/auto), LACP (standard 802.3ad, active/passive – doporučeno), Static (on)
  • Active+Active ✓, Active+Passive ✓, Passive+Passive ✗ (oba pasivní)
  • Všechny linky musí být identické (speed, duplex, VLAN, mode)
  • Konfigurace: channel-group <č> mode active

FHRP (VIRTUÁLNÍ GATEWAY)

  • Více routerů sdílí virtuální IP (VIP). PC má gateway = VIP. Active selže → Standby převezme
  • HSRP (Cisco): Active/Standby, preempt OFF default
  • VRRP (standard): Master/Backup, preempt ON default
  • GLBP (Cisco): jediný s load balancing – až 4 AVF forwardují současně!
  • Konfigurace: standby <group> ip <VIP> (HSRP)
