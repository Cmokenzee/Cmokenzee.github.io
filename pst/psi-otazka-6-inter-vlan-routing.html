01

Problém a koncepce

Problém

VLANy jsou izolované broadcast domény. VLAN 10 nemůže komunikovat s VLAN 20 bez routování. L2 switch forwarduje pouze v rámci jedné VLAN – nerozumí IP adresám.

Řešení: Inter-VLAN Routing

Směrování provozu mezi VLANy pomocí L3 zařízení (router nebo L3 switch), které rozumí IP adresám.

Příklad průchodu
1
PC1 (VLAN 10, 192.168.10.5) → PC2 (VLAN 20, 192.168.20.5)
PC1 zjistí, že cíl je v jiné síti → pošle paket na default gateway
2
Gateway (router/L3 switch) přijme paket z VLAN 10
Routing decision → najde cestu do VLAN 20
3
Forwarduje paket do VLAN 20 → PC2 přijme
Klíčové požadavky
  • L3 zařízení – router nebo L3 switch s IP routingem
  • Vlastní podsíť per VLAN – VLAN 10 = 192.168.10.0/24, VLAN 20 = 192.168.20.0/24
  • Default gateway – každé zařízení musí mít nakonfigurovaný gateway (IP L3 zařízení v dané VLAN)

03

Metoda 1: Legacy (Separate Interfaces)

METODA 1 — LEGACY

Separate Physical Interfaces

Status: ZASTARALÉ, nepoužívat

Router má více fyzických interfaces, každý připojený do jiné VLAN přes access port na switchi. Každý interface = default gateway pro jednu VLAN.

[Router] Fa0/0 (192.168.10.1) ←→ Switch access VLAN 10 ←→ PC1 Fa0/1 (192.168.20.1) ←→ Switch access VLAN 20 ←→ PC2 Fa0/2 (192.168.30.1) ←→ Switch access VLAN 30 ←→ PC3

Výhody

Jednoduché pochopení. Jasná fyzická separace. Žádný single point of failure na jednom kabelu.

Nevýhody

Neškálovatelné (max ~10 VLANů). Plýtvání router i switch porty. Více kabelů. Drahé.

Konfigurace routeru
! IP adresa na každém fyzickém interface
interface FastEthernet0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
interface FastEthernet0/1
ip address 192.168.20.1 255.255.255.0
no shutdown

Na switchi: access porty pro každou VLAN směrem k routeru.

04

Metoda 2: Router-on-a-Stick

METODA 2 — ROUTER-ON-A-STICK

Subinterfaces + 802.1Q Trunk

Použití: malé sítě, branch offices (10–50 uživatelů)

Jeden fyzický trunk interface na routeru, logické subinterfaces (jeden per VLAN) s 802.1Q tagging. Každý subinterface = gateway pro jednu VLAN.

[Router] Fa0/0 (fyzický trunk, BEZ IP!) ├─ Fa0/0.10 (192.168.10.1) ← subinterface VLAN 10 ├─ Fa0/0.20 (192.168.20.1) ← subinterface VLAN 20 └─ Fa0/0.30 (192.168.30.1) ← subinterface VLAN 30 │ ↓ TRUNK (802.1Q tagged) [Switch] Gi0/1 trunk → access ports → PC1, PC2, PC3
Jak to funguje
1
PC1 (VLAN 10) → paket na gateway 192.168.10.1
2
Switch přidá 802.1Q tag (VID=10) → pošle na trunk
3
Router přijme → tag VID=10 → subinterface Fa0/0.10
4
Routing decision → cíl v 192.168.20.0/24 → Fa0/0.20
5
Router přidá tag VID=20 → pošle zpět na trunk
6
Switch forwarduje do VLAN 20 → PC2 přijme

Výhody

Škálovatelné (stovky VLANů). 1 kabel, 1 router port. Flexibilní – snadné přidání VLAN. Nákladově efektivní.

Nevýhody

Bottleneck – všechny VLANy sdílí 1 trunk link. Software routing (CPU) → pomalejší. Single point of failure. Hairpin turn → vyšší latence.

Kritické pravidlo

Fyzický interface NEMÁ IP adresu! IP adresy mají pouze subinterfaces. Klíčový příkaz: encapsulation dot1Q <VLAN_ID>

Konfigurace routeru (Router-on-a-Stick)
! Fyzický interface – BEZ IP, jen aktivace
interface FastEthernet0/0
no shutdown

! Subinterfaces s 802.1Q encapsulation
interface FastEthernet0/0.10
encapsulation dot1Q 10
ip address 192.168.10.1 255.255.255.0

interface FastEthernet0/0.20
encapsulation dot1Q 20
ip address 192.168.20.1 255.255.255.0

interface FastEthernet0/0.30
encapsulation dot1Q 30
ip address 192.168.30.1 255.255.255.0
Konfigurace switche
! Trunk port k routeru
interface GigabitEthernet0/1
switchport mode trunk
switchport trunk allowed vlan 10,20,30

! Access porty pro PC
interface FastEthernet0/1
switchport mode access
switchport access vlan 10
05

Metoda 3: L3 Switch (SVI)

METODA 3 — L3 SWITCH (STANDARD)

Switched Virtual Interfaces (SVI)

Použití: Enterprise (50+ uživatelů), datacentra, campus

L3 switch vytvoří SVI (virtuální interface) pro každou VLAN. Routing probíhá lokálně na switchi v hardware (ASIC) → velmi rychlé!

[L3 Switch] SVI VLAN 10: 192.168.10.1 (virtual gateway) SVI VLAN 20: 192.168.20.1 (virtual gateway) SVI VLAN 30: 192.168.30.1 (virtual gateway) ├─ Access ports VLAN 10 ←→ PC1 ├─ Access ports VLAN 20 ←→ PC2 └─ Access ports VLAN 30 ←→ PC3 Routing = LOKÁLNĚ v hardware (ASIC), žádný external router!
Jak to funguje
1
PC1 (VLAN 10) → paket na gateway 192.168.10.1 (SVI)
2
L3 switch přijme → routing decision v ASIC hardware
Dest 192.168.20.5 → directly connected via VLAN 20
3
Změní MAC adresy, forwarduje lokálně do VLAN 20
Latence ~mikrosekund! Celý proces v hardware.

Výhody

Nejrychlejší – ASIC hardware routing (Mpps). Nízká latence (<10 µs). Propustnost 10–100+ Gbps. Škálovatelné (tisíce VLANů). Redundance (HSRP/VRRP).

Nevýhody

Dražší než L2 switch. Omezené WAN features – potřeba dedikovaný router pro Serial, NAT, VPN. Není náhrada za WAN router!

Kritické!

Bez příkazu ip routing switch nebude routovat mezi VLANy! SVI budou existovat, ale inter-VLAN komunikace nebude fungovat.

Konfigurace L3 switche
! Vytvoření VLANů
vlan 10
name Sales
vlan 20
name Engineering
vlan 30
name HR

! SVI = virtual gateway per VLAN
interface vlan 10
ip address 192.168.10.1 255.255.255.0
no shutdown
interface vlan 20
ip address 192.168.20.1 255.255.255.0
no shutdown
interface vlan 30
ip address 192.168.30.1 255.255.255.0
no shutdown

! KRITICKÉ – zapni routing!
ip routing

! Access porty
interface range Fa0/1 - 10
switchport mode access
switchport access vlan 10
Porovnání rychlosti: L3 switch vs Router
Router (CPU)
~500 Kpps
L3 Switch (ASIC)
160 Mpps (320× rychlejší!)

Catalyst 3850: 160 Mpps. Router 2911: ~500 Kpps. Rozdíl: 320×.

06

Routing schopnosti L3 switche

L3 switch má plnohodnotné routing schopnosti – nejen inter-VLAN routing.

Co L3 switch umí
  • Static routing – ip route <network> <mask> <next_hop>
  • Dynamic routing – OSPF, EIGRP, BGP
  • Policy-Based Routing – routing podle source IP, port, protocol
  • VRF – více routing tables na jednom switchi (izolace)
  • Multicast routing – PIM, IGMP Snooping (IPTV, streaming)
  • IPv6 routing – plná podpora
Co L3 switch NEUMÍ (potřeba dedikovaný router/firewall)
  • WAN interfaces – Serial, T1/E1, cellular
  • NAT/PAT – omezená nebo žádná podpora
  • VPN – IPsec, SSL VPN
  • Advanced firewall – stateful inspection, IPS, application filtering
Typická architektura: [Internet] ←→ [Firewall/Router] ←→ [L3 Core Switch] ←→ [L2 Access Switches] ←→ [PC] NAT, VPN, WAN Inter-VLAN, OSPF VLAN assignment

Doporučení podle velikosti sítě

Malá (5–20 uživatelů)

Router-on-a-Stick. 2–3 VLANy. L2 switch + router levnější než L3 switch. Nízký inter-VLAN provoz.

Střední (20–100 uživatelů)

L3 switch doporučeno (nebo RoaS při omezeném budgetu). 5–10 VLANů. Lepší výkon s L3.

Velká (100+ uživatelů)

L3 switch POUZE. 10+ VLANů. Vysoký provoz vyžaduje hardware routing, nízkou latenci. VoIP, video.

09

Shrnutí klíčových bodů

Na zkoušku si zapamatuj
  • Inter-VLAN routing vyžaduje L3 zařízení (router / L3 switch). VLANy jsou izolované → bez routování nekomunikují
  • Default gateway na PC = IP adresa SVI (L3 switch) nebo subinterface (Router-on-a-Stick)
  • LEGACY Každá VLAN = vlastní interface routeru. Max ~10 VLANů. Nepoužívat!
  • ROUTER-ON-A-STICK 1 trunk, subinterfaces (encapsulation dot1Q). Fyzický interface BEZ IP! Bottleneck na trunk. Malé sítě (<50 uživatelů)
  • L3 SWITCH SVI (interface vlan), ip routing MUSÍ být enabled! ASIC hardware → 320× rychlejší než router. STANDARD pro Enterprise
  • Rychlost: L3 Switch >>> Router-on-a-Stick > Legacy
  • Latence: L3 Switch (<10 µs) <<< Router-on-a-Stick (hairpin turn)
  • L3 switch ≠ WAN router – nemá Serial, NAT, VPN → potřeba dedikovaný firewall/router
  • Klíčové příkazy: Legacy: ip address per interface. RoaS: encapsulation dot1Q <VID> + ip address na subinterface. L3 Switch: interface vlan <VID> + ip address + ip routing
