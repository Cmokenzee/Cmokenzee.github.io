01

Co je OSI model a proč existuje

OSI (Open Systems Interconnection) je referenční model od ISO (1984). Rozděluje síťovou komunikaci do 7 vrstev, z nichž každá má jasně definovanou odpovědnost.

Proč existuje?
  • Standardizace – zařízení různých výrobců spolu komunikují
  • Modularita – změna v jedné vrstvě neovlivní ostatní
  • Troubleshooting – izoluješ problém na konkrétní vrstvu
Protokol vs. Rozhraní

Protokol = horizontální komunikace → stejná vrstva, různá zařízení (např. HTTP mezi prohlížečem a serverem)

Rozhraní = vertikální komunikace → různé vrstvy, stejné zařízení (např. aplikace volá send() přes socket API)

PDU a zapouzdření

PDU (Protocol Data Unit) je jednotka dat specifická pro každou vrstvu. Každá vrstva přidává svou hlavičku (header) – tomu říkáme zapouzdření (encapsulation).

L7–L5: DATA → L4: SEGMENT / DATAGRAM → L3: PAKET → L2: RÁMEC → L1: BITY
Zapouzdření vs. dekapsulace

Zapouzdření = odesílání: L7→L1, každá vrstva přidává svůj header.

Dekapsulace = příjem: L1→L7, každá vrstva odstraňuje svůj header.

Příklad zapouzdření HTTP požadavku
L7
Aplikace vytvoří HTTP GET požadavek
PDU = DATA (HTTP zpráva)
L4
Přidá TCP hlavičku (+20 B)
Source port, dest port (80), sequence number, flags → PDU = SEGMENT
L3
Přidá IP hlavičku (+20 B)
Source IP, dest IP, TTL, protocol (6=TCP) → PDU = PAKET
L2
Přidá Ethernet header (+14 B) a FCS trailer (+4 B)
Dest MAC, source MAC, EtherType (0x0800) → PDU = RÁMEC
L1
Převod na signály
Elektrické / optické / rádiové → PDU = BITY
04

Vrstvy v detailu

L1 — FYZICKÁ

Physical Layer

PDU: Bity Zařízení: Hub, Repeater

Přenos surových bitů (0 a 1) přes fyzické médium. Definuje elektrické, mechanické a funkční parametry spojení.

  • Kódování – Manchester, NRZ, 4B/5B
  • Modulace – ASK, FSK, PSK (modemy, Wi-Fi)
  • Synchronizace hodin odesílatele a příjemce
  • Multiplexing – TDM, FDM, WDM
Přenosová média
  • Měděný kabel – UTP (Cat5e = 1 Gbps, Cat6 = 10 Gbps), STP, koaxiální
  • Optické vlákno – Single-mode (desítky km, laser), Multi-mode (do 2 km, LED). Imunní vůči EMI, 100 Gbps+
  • Bezdrátové – Wi-Fi (802.11), Bluetooth, 4G/5G, satelit
L2 — LINKOVÁ

Data Link Layer

PDU: Rámec (Frame) Zařízení: Switch, Bridge, AP

Spolehlivý přenos rámců mezi přímo spojenými uzly. Přidává MAC adresování a detekci chyb.

Dvě podvrstvy

  • LLC (Logical Link Control) – multiplexování protokolů, flow control
  • MAC (Media Access Control) – MAC adresy, přístup k médiu, formátování rámců

MAC adresa

48-bit (6 B) unikátní adresa síťové karty. Formát: AA:BB:CC:DD:EE:FF. První 3 B = OUI (výrobce), poslední 3 B = unikátní číslo. Broadcast: FF:FF:FF:FF:FF:FF.

Přístup k médiu

  • CSMA/CD – Ethernet (detekce kolizí, dnes full-duplex → není potřeba)
  • CSMA/CA – Wi-Fi (vyhýbání se kolizím)

Detekce chyb

FCS (Frame Check Sequence) – 4 B CRC-32 na konci rámce. Chyba → rámec zahozen (neopravuje, oprava je na TCP).

Struktura Ethernet rámce
  • Preamble (7 B) + SFD (1 B) – synchronizace
  • Destination MAC (6 B) + Source MAC (6 B)
  • EtherType (2 B) – 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6
  • Payload (46–1500 B) – min. 46 B (jinak padding)
  • FCS (4 B) – CRC-32
  • Celkem: 64–1518 B (bez preamble). Jumbo frames: až 9000 B
L3 — SÍŤOVÁ

Network Layer

PDU: Paket (Packet) Zařízení: Router, L3 Switch

Logické adresování a směrování paketů přes různé sítě. Umožňuje komunikaci mezi zařízeními v různých LAN/WAN.

IP adresy

  • IPv4 – 32 bit, 4.3 mld adres, formát: 192.168.1.1
  • IPv6 – 128 bit, formát: 2001:0db8:85a3::8a2e:0370:7334

Routing

Routery používají routing tabulky (destination network, next hop, metric). Routing protokoly: RIP (distance vector, max 15 hopů), OSPF (link state), BGP (internet backbone), EIGRP (Cisco).

Fragmentace

Pokud paket > MTU (Ethernet = 1500 B) → fragmentace. IPv4: routery mohou fragmentovat. IPv6: fragmentuje POUZE zdroj.

TTL (Time To Live)

Každý router sníží TTL o 1. Když TTL = 0 → paket zahozen + ICMP Time Exceeded. Využívá traceroute.

IPv4 hlavička (20 B)

Version, IHL, DSCP, Total Length, Identification, Flags (DF, MF), Fragment Offset, TTL, Protocol (1=ICMP, 6=TCP, 17=UDP), Header Checksum, Source IP, Destination IP, Options

L4 — TRANSPORTNÍ

Transport Layer

PDU: Segment (TCP) / Datagram (UDP) Implementace: v koncových zařízeních (ne routerech!)

End-to-end spojení mezi aplikacemi. Segmentace dat, multiplexing portů, spolehlivý (TCP) nebo nespolehlivý (UDP) přenos.

Porty (16 bit, 0–65535)

  • Well-known (0–1023): HTTP 80, HTTPS 443, SSH 22, FTP 21, DNS 53, SMTP 25
  • Registered (1024–49151): registrované aplikace
  • Dynamic/Ephemeral (49152–65535): dočasné

TCP Connection-oriented

Spolehlivý – ACK, sequence numbers, retransmission, flow control, congestion control. Header 20 B.

UDP Connectionless

Nespolehlivý – žádné ACK, žádné pořadí. Rychlý, nízký overhead. Header 8 B. DNS, VoIP, streaming, hry.

TCP Three-way Handshake
1
SYN → (klient → server)
SYN=1, seq=1000. „Chci navázat spojení."
2
SYN-ACK ← (server → klient)
SYN=1, ACK=1, seq=5000, ack=1001. „Souhlasím, potvrzuji tvé 1000."
3
ACK → (klient → server)
ACK=1, seq=1001, ack=5001. „Potvrzuji, spojení navázáno!"
TCP Four-way Handshake (ukončení)
1
FIN → klient chce ukončit
2
ACK ← server potvrzuje FIN
3
FIN ← server chce ukončit
4
ACK → klient potvrzuje, spojení uzavřeno
L5 — RELAČNÍ (Session)

Session Layer

PDU: DataV TCP/IP neexistuje samostatně!

Spravuje relace – navázání, udržování, ukončení. Dialog control (half/full-duplex), checkpointing (restart od posledního bodu, ne od začátku).

Příklady: NetBIOS, RPC, SIP, web cookies/session IDs, JWT tokeny.

L6 — PREZENTAČNÍ (Presentation)

Presentation Layer

PDU: DataV TCP/IP neexistuje samostatně!
  • Kódování – ASCII, Unicode (UTF-8), byte order
  • Šifrování – TLS/SSL (HTTPS), AES, RSA
  • Komprese – gzip, JPEG, H.264, MP3
  • Serializace – JSON, XML, Protocol Buffers
L7 — APLIKAČNÍ (Application)

PDU: Data / MessageV TCP/IP zahrnuje L5+L6+L7

OSI vs. TCP/IP

OSI (7 vrstev)TCP/IP (4 vrstvy)Poznámka
L7 + L6 + L5ApplicationVše v jedné vrstvě
L4 TransportTransportStejné – TCP, UDP
L3 NetworkInternetStejné – IP, ICMP
L2 + L1Network AccessEthernet + fyzická v jedné
Rozdíly
  • OSI = teoretický standard (ISO, 1984), 7 vrstev, obecné popisy funkcí
  • TCP/IP = praktická implementace internetu (DARPA, 1970s), 4 vrstvy, konkrétní protokoly
  • OSI se stále používá pro výuku, troubleshooting a komunikaci mezi odborníky

Síťové prvky a průchod dat

L1 – Hub / Repeater (zastaralé)

Pracují POUZE s bity. Nerozumí adresám. Hub přijme signál → pošle kopii na VŠECHNY porty (broadcast). Sdílený collision domain.

L2 – Switch

Pracuje s rámci a MAC adresami. Unicast forwarding podle MAC tabulky (CAM table). Odděluje collision domains.

Průchod dat switchem
1
Přijme rámec, zkontroluje FCS (CRC)
2
MAC learning – uloží source MAC → port do tabulky
3
Lookup destination MAC v tabulce
Nalezeno → unicast na správný port. Nenalezeno → flooding na všechny porty kromě příchozího. Broadcast MAC → flood.
4
Přepošle rámec beze změny (MAC adresy NEMĚNÍ!)

L3 – Router

Pracuje s pakety a IP adresami. Směruje mezi sítěmi. Odděluje broadcast domains.

Průchod dat routerem
1
Přijme rámec, zkontroluje dest MAC (musí být MAC routeru)
2
Odstraní L2 header → zbyde IP paket
3
Routing decision – lookup dest IP v routing tabulce (longest prefix match)
4
Sníží TTL o 1 (TTL=0 → zahodí + ICMP)
5
ARP lookup pro next hop MAC (nebo cache)
6
Vytvoří NOVÝ L2 rámec (nové source + dest MAC!), IP paket NEZMĚNĚN
Klíčový rozdíl!

Router MĚNÍ MAC adresy na každém hopu. IP adresy zůstávají STEJNÉ ze zdroje do cíle.
TTL se snižuje na každém routeru (L3), ne na switchi (L2).

L3 Switch (Multilayer)

Kombinace L2 switche + L3 routeru. Stejná VLAN → chová se jako L2 switch (MAC forwarding). Různé VLANy → chová se jako router (IP routing, mění MAC, snižuje TTL). Hardware-based = rychlejší než separátní router. Používá se v Enterprise LAN (inter-VLAN routing).

Firewall (L3–L7)

Packet Filtering (L3/L4)

Filtruje podle IP, portů, protokolu. Stateless – každý paket samostatně.

Stateful (L3/L4)

Sleduje TCP spojení (connection table). Povolí jen pakety patřící existujícímu spojení.

Application / NGFW (L7)

DPI – kontrola obsahu. WAF, IPS. Detekce malware, SQL injection, XSS.

Diagnostické nástroje

Wireshark L1–L7 GUI packet capture & analýza. Display/capture filters, protocol dissectors, Follow TCP Stream.
tcpdump L2–L4 CLI packet capture (Linux). Lehký, rychlý, ukládá .pcap.
ping L3 ICMP Echo Request/Reply. Test reachability, měření RTT, packet loss.
traceroute L3 Mapování cesty hop-by-hop pomocí TTL. Identifikace kde paket „padá".
netstat / ss L3–L4 Aktivní spojení, listening porty, routing tabulka. ss = modernější náhrada.
nslookup / dig L7 DNS dotazy – překlad doménových jmen → IP. Troubleshooting DNS.
iperf L4 Měření propustnosti sítě (bandwidth, jitter, packet loss). Client-server.
nmap L3–L4 Port scanning, host discovery, OS detection. Security audit.
MTR L3 Kombinace ping + traceroute. Continuous monitoring per hop.
arp / arp-scan L2–L3 ARP cache, skenování LAN, detekce IP konfliktů a ARP spoofing.

Troubleshooting

Bottom-Up (L1→L7)

Začni od kabelů a fyziky → MAC → IP → porty → aplikace. Dobré pro hardware problémy.

Top-Down (L7→L1)

Začni od aplikace → DNS → porty → IP → MAC → kabely. Rychlejší pro app problémy.

Divide & Conquer

Začni kde suspektuješ problém, pak nahoru/dolů podle potřeby. Nejefektivnější.

Příklad: „Web stránka se nenačítá"
L7
Zkontroluj DNS: nslookup domena.cz
L4
Zkontroluj porty: netstat -tuln, firewall povoluje port 80/443?
L3
Ping serveru: ping server-ip, traceroute
L2
Zkontroluj MAC/VLAN: arp -a, switch port status
L1
Zkontroluj kabely, link lights, konektory

Shrnutí klíčových bodů

Na zkoušku si zapamatuj
  • Router MĚNÍ MAC, NEMĚNÍ IP – IP adresy jsou stejné ze zdroje do cíle, MAC se mění na každém hopu
  • Switch = L2 (MAC), Router = L3 (IP)
  • TTL se snižuje na routeru (L3), ne na switchi (L2)
  • Broadcast domain odděluje router/L3 switch. Collision domain odděluje switch/bridge
  • PDU: Data → Segment/Datagram → Packet → Frame → Bits
  • TCP = spolehlivý (ACK, handshake, 20 B header). UDP = rychlý (žádné ACK, 8 B header)
  • OSI = 7 vrstev (teorie). TCP/IP = 4 vrstvy (praxe). L5+L6 v TCP/IP neexistují samostatně
  • Zapouzdření = shora dolů (L7→L1). Dekapsulace = zdola nahoru (L1→L7)
  • L2 detekuje chyby (FCS/CRC), ale neopravuje – opravu řeší TCP na L4
