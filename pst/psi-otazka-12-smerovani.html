01

Směrování – základní pojmy

Směrování (routing) = proces určování nejlepší cesty paketu přes síť routerů. Router přijme paket → zkontroluje Dest IP → konzultuje routing table → vybere best path → forwarduje.

Klíčové pojmy
  • Routing table – databáze známých sítí a cest (network, next-hop, metric, AD, interface)
  • Next-hop – IP adresa dalšího routeru na cestě k cíli
  • Metric – kvalita cesty (nižší = lepší). Každý protokol má vlastní
  • Administrative Distance (AD) – důvěryhodnost zdroje route (0–255, nižší = lepší)
  • Konvergence – stav kdy všechny routery mají konzistentní tabulky

03

Administrativní vzdálenost (AD)

Číslo 0–255 vyjadřující důvěryhodnost zdroje route. Nižší AD = lepší. Rozhoduje mezi routes ze RŮZNÝCH zdrojů pro stejnou síť.

Connected0
Static1
eBGP20
EIGRP int90
OSPF110
RIP120
EIGRP ext170
iBGP200
AD vs Metric – pravidlo!

AD porovnává MEZI protokoly (OSPF vs RIP vs Static).

Metric porovnává UVNITŘ jednoho protokolu (OSPF cesta A vs OSPF cesta B).

Pořadí: Nejprve AD → pokud stejné AD → metric → pokud stejné metric → load balancing (ECMP).

OSPF cost – příklady

Default reference bandwidth = 100 Mbps (100,000,000):

  • FastEthernet (100 Mbps): 100M / 100M = 1
  • GigabitEthernet (1 Gbps): 100M / 1000M = 0.1 → zaokrouhleno na 1 (problém!)
  • T1 (1.544 Mbps): 100M / 1.544M ≈ 65
  • Serial 64 Kbps: 100M / 0.064M = 1562

Řešení: auto-cost reference-bandwidth 10000 (pro 10G sítě)

05

Statické směrování

Administrátor manuálně nakonfiguruje každou route. Router nekomunikuje s ostatními ohledně cest.

Výhody

Žádný overhead (šetří BW, CPU). Bezpečné (žádné fake routes). Plná kontrola. Předvídatelné. Jednoduché pro malé sítě.

Nevýhody

Neškálovatelné (100 routerů = stovky routes!). Žádná auto-konvergence (link selže → admin musí ručně). Chybovost (překlep). Žádný auto load balancing.

Kdy použít statické
  • Malé sítě (2–5 routerů), jednoduchá topologie
  • Stub networks – síť s jedinou cestou ven (default route stačí)
  • Floating static – backup route s vyšším AD (failover)
  • Security – DMZ, kritické prostředí
06

Dynamické směrování

Routery automaticky vyměňují informace o sítích pomocí routing protocols. Učí se a adaptují na změny.

Výhody

Škálovatelné (tisíce routerů, Internet = BGP 900K+ routes). Auto-konvergence (sekundy–minuty). ECMP load balancing. Fault tolerance.

Nevýhody

Overhead (BW, CPU, RAM). Komplexnější konfigurace. Bezpečnostní rizika (fake routes → mitigace: authentication). Konvergenční čas.

07

Distance-Vector protokoly

Princip: „Routing by rumor"

Router zná pouze vzdálenost (distance = metrika) a směr (vector = next-hop) k cíli. Nezná kompletní topologii!

  • Periodicky posílá celou routing table sousedům (RIP: 30 s)
  • Soused přijme → přidá cost svého linku → přepočítá (Bellman-Ford algoritmus)
  • Informace se šíří hop-by-hop
Problémy a řešení
  • Counting to Infinity – route osciluje po výpadku (cost 1→2→…→16)
  • Split Horizon – neposílej route zpět na interface, odkud přišla
  • Route Poisoning – oznámíš failed route jako unreachable (metric=16)
  • Hold-down timer – čekej X sekund po změně (stabilizace)
  • Triggered updates – pošli update okamžitě při změně

Protokoly: RIP, EIGRP (hybrid).

08

Link-State protokoly

Princip: „Kompletní mapa sítě"

Každý router zná celou topologii (LSDB = Link-State Database). Vypočítá nejlepší cesty Dijkstra SPF algoritmem.

1
Hello packets → neighbor discovery
2
LSA (Link-State Advertisement) → popis SVÝCH linků
3
Flooding LSA → všem routerům v area (jednou, ne periodic!)
4
LSDB → kompletní topologická databáze
5
SPF výpočet → Dijkstra → routing table

Výhody: Rychlá konvergence (sekundy), žádné loops (SPF), efektivní updates (pouze při změně), škálovatelné (areas).

Nevýhody: Vyšší CPU/RAM (LSDB + SPF), komplexnější konfigurace, initial flooding.

Protokoly: OSPF, IS-IS.

10

RIP

RIP – Routing Information Protocol

Distance-Vector IGP. Metrika: hop count (max 15, 16 = unreachable). AD: 120. Updates: periodic 30 s, celá tabulka.

VerzeRokKlíčové vlastnosti
RIPv11988Classful (bez subnet mask!), broadcast, žádná auth. ZASTARALÉ.
RIPv21994Classless (VLSM, CIDR), multicast 224.0.0.9, MD5 auth. Aktuální pro IPv4
RIPng—RIP pro IPv6. Multicast FF02::9. Stejné principy
RIP timery
  • Update: 30 s – jak často se posílají updates
  • Invalid: 180 s – route označena jako invalid
  • Hold-down: 180 s – stabilizace
  • Flush: 240 s – route kompletně odstraněna
11

EIGRP

EIGRP – Enhanced Interior Gateway Routing Protocol

Advanced DV (hybrid) IGP. Cisco proprietární. Metrika: composite (BW + delay). AD: 90/170. Updates: incremental + triggered (ne celá tabulka!). Algoritmus: DUAL (loop-free).

DUAL – klíčové koncepty
  • Successor – nejlepší route (lowest metric), používá se pro forwarding
  • Feasible Successor (FS) – záložní route → okamžitý failover (sub-second!) bez přepočtu
  • Feasibility Condition: Advertised Distance souseda < Feasible Distance → zabraňuje loops

Výhody: Velmi rychlá konvergence (sub-second díky FS), efektivní, unequal-cost load balancing. Nevýhody: Cisco proprietární (vendor lock-in).

12

OSPF

OSPF – Open Shortest Path First ENTERPRISE STANDARD

Link-State IGP. Open standard. Verze: OSPFv2 (IPv4), OSPFv3 (IPv6). Metrika: cost (10⁸/BW). AD: 110. Algoritmus: Dijkstra SPF.

Areas (hierarchie)
  • Area 0 (Backbone) – centrální area, musí existovat, propojuje ostatní
  • Area 1, 2… – non-backbone, připojeny k Area 0
  • ABR (Area Border Router) – router mezi areas
  • ASBR (AS Boundary Router) – router mezi OSPF a jiným protokolem

Proč areas? LSDB omezena na area → menší SPF výpočty → škálovabilita.

LSA typy a DR/BDR
  • Type 1 (Router): Popis routeru a linků uvnitř area
  • Type 2 (Network): Multi-access segment, generován DR
  • Type 3 (Summary): Inter-area routes (ABR)
  • Type 5 (External): Externí routes (redistribuce)

DR/BDR: Na Ethernet segmentech se volí Designated Router a Backup DR → centralizace LSA exchange, snížení floodingu.

13

BGP

BGP – Border Gateway Protocol "Routing protocol of the Internet"

Path-Vector EGP. RFC 4271 (BGP-4). Transport: TCP port 179. Routing mezi Autonomous Systems (AS).

AD: 20 (eBGP – mezi AS) / 200 (iBGP – uvnitř AS).

Path Attributes (metrika)
  • AS_PATH – seznam AS na cestě. Kratší = lepší. Detekce loops (vlastní AS = loop)
  • LOCAL_PREF – lokální preference (vyšší = lepší). Rozhoduje odchod z AS
  • MED – hint sousedovi o preferovaném vstupu (nižší = lepší)

Výhody: Škálovatelné (900K+ routes), policy-based, loop prevention. Nevýhody: Velmi komplexní, pomalá konvergence, velká paměť.

Příklady konfigurace

Topologie: R1 (LAN1 192.168.1.0/24) — 10.0.0.0/30 — R2 (LAN2 192.168.2.0/24) — 10.0.0.4/30 — R3 (LAN3 192.168.3.0/24)

Příklad 1: Statické směrování (R1)
ip route 192.168.2.0 255.255.255.0 10.0.0.2 ! k LAN2 přes R2
ip route 192.168.3.0 255.255.255.0 10.0.0.2 ! k LAN3 přes R2
ip route 10.0.0.4 255.255.255.252 10.0.0.2 ! k linku R2-R3

Výsledek: S 192.168.2.0/24 [1/0] via 10.0.0.2. Žádná auto-konvergence!

Příklad 2: RIPv2 (všechny routery)
! R1
router rip
version 2
network 192.168.1.0
network 10.0.0.0
no auto-summary

! R2
router rip
version 2
network 10.0.0.0
network 192.168.2.0
no auto-summary

! R3
router rip
version 2
network 10.0.0.0
network 192.168.3.0
no auto-summary
Výsledná tabulka R1 (RIPv2)
C 192.168.1.0/24 is directly connected, GigabitEthernet0/0
C 10.0.0.0/30 is directly connected, Serial0/0/0
R 192.168.2.0/24 [120/1] via 10.0.0.2, Serial0/0/0
R 192.168.3.0/24 [120/2] via 10.0.0.2, Serial0/0/0
R 10.0.0.4/30 [120/1] via 10.0.0.2, Serial0/0/0

R = RIP. [120/1] = AD 120 / 1 hop. [120/2] = 2 hopy (R1→R2→R3). Link selže → triggered update → auto-konvergence!

15

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

AD A METRIKA

  • AD porovnává MEZI protokoly (nižší = lepší). Connected=0, Static=1, EIGRP=90, OSPF=110, RIP=120
  • Metric porovnává UVNITŘ protokolu. AD má VŽDY přednost před metrikou!
  • Routing table: Network, Next-hop, Metric, AD, Interface. Kódy: C/S/R/D/O/B

STATICKÉ vs DYNAMICKÉ

  • Statické: manuální, žádný overhead, žádná auto-konvergence. Malé sítě, stub, default route
  • Dynamické: auto-učení, konvergence, škálovatelné, ECMP. Velké sítě, redundance

DV vs LS

  • DV Bellman-Ford, periodic (30 s), celá tabulka, POMALÉ (minuty), loops možné. RIP, EIGRP
  • LS Dijkstra SPF, event-triggered (LSA), RYCHLÉ (sekundy), žádné loops, areas. OSPF, IS-IS

PROTOKOLY

  • RIP: hop count (max 15), AD=120, 30 s periodic. RIPv2: CIDR, multicast 224.0.0.9. RIPng: IPv6
  • EIGRP: composite (BW+delay), AD=90, DUAL (Successor + Feasible Successor → sub-second failover). Cisco
  • OSPF: cost (10⁸/BW), AD=110, Dijkstra SPF, areas (Area 0 backbone), LSA/LSDB. Enterprise standard!
  • BGP: path attributes (AS_PATH, LOCAL_PREF, MED), AD=20/200, TCP 179. Internet routing, eBGP/iBGP

KONFIGURACE

  • Static: ip route <network> <mask> <next-hop> → [1/0] v tabulce
  • RIPv2: router rip / version 2 / network X.X.X.X / no auto-summary → [120/hops]
  • Link selže → RIP triggered update → auto-konvergence. Static → admin musí ručně!
