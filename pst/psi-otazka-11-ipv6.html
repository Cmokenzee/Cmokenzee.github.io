01

Specifikace a vlastnosti IPv6

IPv6 = Internet Protocol version 6. Náhrada za IPv4 (vyčerpáno 2011). Standard: RFC 8200.

Proč IPv6?

IPv4: 4.3 miliardy adres (2³²) – nestačí! NAT řeší dočasně, ale komplikuje end-to-end komunikaci.

IPv6: 2¹²⁸ = 340 undecillion adres. Každé zařízení na planetě může mít unikátní veřejnou IP.

Základní vlastnosti
  • 128 bitů adresní prostor (8 hextetů, hex zápis)
  • Header 40 B fixní (vs IPv4 20–60 B proměnná) → jednodušší, rychlejší forwarding
  • No fragmentation routerem (pouze source, Path MTU Discovery povinné)
  • No broadcast – nahrazeno multicastem
  • No checksum v IP headeru (redundantní – L2 + L4 mají checksums)
  • SLAAC – autoconfiguration bez DHCP serveru
  • IPsec povinné (v IPv4 volitelné)
IPv6 Header (40 B)
  • Version (4 b) = 6
  • Traffic Class (8 b) – QoS
  • Flow Label (20 b) – identifikace flow pro QoS
  • Payload Length (16 b) – délka payloadu (bez headeru)
  • Next Header (8 b) – typ dalšího headeru (TCP=6, UDP=17, ICMPv6=58)
  • Hop Limit (8 b) – ekvivalent TTL (decremented každým routerem)
  • Source / Destination Address (128 + 128 b)

Extension Headers: volitelné, chainované pomocí Next Header field (routing, fragmentation, security).

03

Migrace (Dual-Stack, Tunel, NAT64)

IPv6 není backward compatible s IPv4 → potřeba migračních technik.

1. Dual-Stack

Zařízení má IPv4 i IPv6 současně. Happy Eyeballs: IPv6 first, fallback IPv4. Nejběžnější (Google, Facebook, ISP). Nevýhoda: dvojí konfigurace.

2. Tunelování

IPv6 paket enkapsulován do IPv4 (protocol=41) → přenesen přes IPv4 síť → dekapsulován. Manuální tunely (site-to-site). 6to4/Teredo = deprecated. Dočasné řešení.

3. NAT64 + DNS64

IPv6-only síť ↔ IPv4-only server. DNS64 syntetizuje AAAA z A recordu (prefix 64:ff9b::). NAT64 gateway překládá IPv6↔IPv4. Použití: mobile networks (LTE/5G).

NAT64 – jak to funguje krok za krokem
1
IPv6 klient chce přistoupit na IPv4 server (93.184.216.34)
2
DNS64 syntetizuje AAAA record
64:ff9b:: + 93.184.216.34 → 64:ff9b::5db8:d822
3
Klient pošle IPv6 paket na 64:ff9b::5db8:d822
4
NAT64 gateway přeloží IPv6 → IPv4 a přepošle
5
Server odpoví IPv4 → NAT64 přeloží zpět → klient přijme IPv6
04

Formát adresy a komprimace nul

128 bitů = 8 skupin po 16 bitech (hextetů), hexadecimální, odděleno dvojtečkami. Prefix notation: CIDR (např. /64).

Dvě pravidla komprimace

Pravidlo 1: Vedoucí nuly v hextetu můžeš vynechat → 0db8 → db8, 0042 → 42, 0000 → 0

Pravidlo 2: Souvislou sekvenci nulových hextetů nahraď :: → ale pouze JEDNOU! (jinak nejasné kolik nul)

Příklad komprimace
Full: 2001:0db8:0000:0000:0000:ff00:0042:8329
Krok 1: 2001:db8:0:0:0:ff00:42:8329
Krok 2: 2001:db8::ff00:42:8329
Další příklady
fe80:0000:0000:0000:0000:0000:0000:0001 → fe80::1
0000:0000:0000:0000:0000:0000:0000:0001 → ::1 (loopback)
0000:0000:0000:0000:0000:0000:0000:0000 → :: (unspecified)

Typické prefixy: /64 (subnet), /48 (site/organizace), /32 (ISP allocation).

06

Druhy vysílání

Unicast (1:1)

One-to-one. Paket doručen jednomu příjemci. Typy: GUA (veřejná), ULA (privátní), Link-Local (lokální).

Multicast (1:many)

One-to-many. Prefix ff00::/8. Scope: link-local (2), site (5), global (e). ff02::1 = all nodes. ff02::2 = all routers. Efektivnější než broadcast.

Anycast (1:nearest)

One-to-nearest. Více zařízení se stejnou adresou → routing vybere nejbližší. Load balancing, DNS root servery. Vypadá jako unicast (stejný formát).

NO BROADCAST! IPv6 nemá broadcast. Místo toho multicast ff02::1 (all nodes on link) = náhrada za broadcast.

07

Druhy IPv6 adres v detailu

GUA – Global Unicast Address (2000::/3)

Veřejné routovatelné (jako public IPv4). Struktura: Prefix /48 (ISP→org) + Subnet ID 16 b (65536 subnetů!) + Interface ID 64 b.

Generování Interface ID:

  • EUI-64 – z MAC adresy (48→64 b, vložení fffe, inverzní U/L bit). Bezpečnostní riziko (MAC trackovatelné)
  • Privacy Extensions (RFC 4941) – náhodné ID, mění se periodicky. Výchozí Windows/Linux
  • Manual/Static – administrátor nastaví ručně (::1)
ULA – Unique Local Address (fd00::/8)

Privátní, ne routovatelné v internetu (jako 10.x, 192.168.x). Struktura: fd + 40-bit Global ID (pseudo-random) + 16-bit Subnet + 64-bit Interface ID.

Příklad: fd12:3456:789a:1::1. Použití: interní komunikace, VPN, lab.

Link-Local (fe80::/10)

Auto-generated, vždy přítomna (i bez DHCP/SLAAC). Ne routovatelná. Formát: fe80::/64 + 64-bit Interface ID.

Použití: NDP, routing protocols (OSPF, EIGRP source), lokální komunikace. Pozor: při komunikaci nutno specifikovat interface: ping fe80::1%eth0

Další typy (Loopback, Unspecified, IPv4-mapped, Multicast)
  • ::1/128 (Loopback) – ekvivalent 127.0.0.1, self-test
  • ::/128 (Unspecified) – source před získáním adresy (DHCP/SLAAC request)
  • ::ffff:0:0/96 (IPv4-mapped) – IPv4 v IPv6 formátu, dual-stack aplikace
  • ff00::/8 (Multicast) – ff02::1 all nodes, ff02::2 all routers, ff02::1:ffxx:xxxx solicited-node

NDP – Neighbor Discovery Protocol (RFC 4861)

NDP = náhrada za ARP v IPv6. Používá ICMPv6 messages. Funkce: address resolution (IPv6→MAC), router discovery, SLAAC, DAD, redirect.

RS – Router Solicitation (Type 133)

Host žádá router o konfigurační informace. Při bootu (místo čekání na RA).

Source: host link-local (fe80::) nebo :: | Dest: ff02::2 (all routers multicast)

RA – Router Advertisement (Type 134)

Router oznamuje svou přítomnost a síťové parametry.

  • Prefix(y) pro SLAAC (např. 2001:db8::/64)
  • Default gateway (router link-local = source)
  • Flags: M, O, A – řídí SLAAC vs DHCPv6 (viz níže)
  • MTU, Hop Limit

Periodicky (200 s) NEBO odpověď na RS (okamžitě). Dest: ff02::1 (all nodes) nebo unicast.

NS – Neighbor Solicitation (Type 135)

ARP replacement! Zjištění MAC adresy pro IPv6. Také pro DAD (Duplicate Address Detection).

Address resolution: „Kdo má 2001:db8::1? Pošli mi svou MAC!"

DAD: Před použitím nové adresy → NS s target=nová adresa, source=:: → pokud někdo odpoví → duplicitní IP → nesmí se použít!

Dest: solicited-node multicast (ff02::1:ffxx:xxxx) – efektivnější než broadcast. Jen zařízení s matching adresou zpracovávají.

NA – Neighbor Advertisement (Type 136)

Odpověď na NS. Obsahuje: target IPv6, link-layer (MAC) adresa, flags R/S/O.

Dest: unicast (source z NS) NEBO ff02::1 (unsolicited NA – oznámení změny MAC).

Redirect (Type 137)

Router informuje host o lepší cestě. „Pro tento cíl použij router B místo mě!"

10

DHCPv6 a příznakové bity A, O, M

DHCPv6 = alternativa k SLAAC. Dva módy: Stateful (přiděluje IP + DNS) a Stateless (jen DNS, IP z SLAAC).

Příznakové bity v Router Advertisement

RA obsahuje flags které řídí, jak host získá konfiguraci:

A Autonomous A=1 → použij prefix pro SLAAC (auto-generate IP)
M Managed M=1 → použij Stateful DHCPv6 pro IP adresu
O Other O=1 → použij Stateless DHCPv6 pro DNS/NTP

Kombinace flags

M=0 O=0 A=1 Pouze SLAAC. Host generuje IP z RA prefix. Žádný DHCPv6. DNS manuálně nebo RDNSS v RA.
M=0 O=1 A=1 SLAAC + Stateless DHCPv6 NEJBĚŽNĚJŠÍ
IP z SLAAC (A=1). DNS/NTP z DHCPv6 (O=1). Gateway z RA.
M=1 O=0 A=0 Pouze Stateful DHCPv6. IP + DNS z DHCPv6 serveru. SLAAC nepoužito (A=0). Gateway z RA.
M=1 O=1 A=0 Stateful DHCPv6 (redundantní, M=1 implikuje O=1). Vše z DHCPv6.
Příklad: SLAAC + Stateless DHCPv6 (M=0, O=1, A=1)
1
Host boot → pošle RS (Router Solicitation)
2
Router odpoví RA: M=0, O=1, A=1, Prefix=2001:db8::/64
3
Host generuje IP (SLAAC): 2001:db8::interface-id
4
DAD check (NS s source ::) → ověří unikátnost
5
Host kontaktuje DHCPv6 (O=1): INFORMATION-REQUEST
DHCPv6 odpoví: DNS servers, NTP, domain name.
✓
Host má: IP (SLAAC), DNS (DHCPv6), gateway (RA link-local)
Příklad: Pouze Stateful DHCPv6 (M=1, O=0, A=0)
1
Host boot → RS → Router RA: M=1, A=0
2
Host kontaktuje DHCPv6: SOLICIT
3
DHCPv6 server: ADVERTISE → host REQUEST → server REPLY
IP adresa, DNS, NTP – vše z DHCPv6.
✓
Host má: IP (DHCPv6), DNS (DHCPv6), gateway (RA link-local)

Shrnutí klíčových bodů

Na zkoušku si zapamatuj

SPECIFIKACE A MIGRACE

  • 128 bitů (8 hextetů, hex). Header 40 B fixní. No broadcast, no checksum, no fragmentace routerem. IPsec povinné, SLAAC
  • Komprimace: vedoucí 0 ven, :: pro souvislé nuly (pouze 1×!)
  • Migrace: Dual-Stack (nejběžnější), Tunelování (IPv6-in-IPv4), NAT64+DNS64 (mobile)

PREFIXY A VYSÍLÁNÍ

  • 2000::/3 = GUA (veřejné). fd00::/8 = ULA (privátní). fe80::/10 = Link-Local (auto, vždy)
  • ff00::/8 = Multicast. ::1 = Loopback. :: = Unspecified
  • Unicast (1:1), Multicast (1:many), Anycast (1:nearest). NO broadcast!
  • ff02::1 = all nodes (náhrada broadcast). ff02::2 = all routers

NDP (RFC 4861)

  • RS (133): Host → ff02::2 „pošli RA"
  • RA (134): Router → ff02::1 – prefix, gateway, flags M/O/A
  • NS (135): IPv6→MAC (ARP replacement) + DAD (source ::). Dest: solicited-node multicast
  • NA (136): Odpověď na NS – MAC adresa
  • Redirect (137): Lepší cesta k cíli

DHCPv6 FLAGS

  • A=1 (Autonomous) → SLAAC povoleno (auto-generate IP z prefix)
  • M=1 (Managed) → Stateful DHCPv6 pro IP adresu
  • O=1 (Other) → Stateless DHCPv6 pro DNS/NTP
  • M=0, O=0, A=1 = pouze SLAAC
  • M=0, O=1, A=1 = SLAAC + Stateless DHCPv6 → NEJBĚŽNĚJŠÍ!
  • M=1, O=0, A=0 = pouze Stateful DHCPv6
